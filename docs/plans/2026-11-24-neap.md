# Neap and Spring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Neap, an 8 HP bank of eight slow triangle/sine cycles about an octave apart on uneven steps (after Instruō øchd), with their weighted sum TIDE, a HIGH gate above a MARK, and a polyphonic ALL; and Spring, a 6 HP expander to its right with sixteen derived outputs (FOLD, MIN/MAX, cascading TRIG, STEPS).

**Architecture:**
- **Neap core:** Rack-free headers in `src/neap/`: the tables and rate law (`NeapRate.hpp`), the eight cycles (`Cycles.hpp`), the tide and HIGH (`Tide.hpp`), and the engine that ties them to a frame of params and inputs (`NeapEngine.hpp`).
- **Spring core:** `src/spring/SpringCore.hpp` turns eight shaped cycle values into the sixteen outputs and keeps the link state.
- **Link:** `src/neap/NeapExpander.hpp` is the interface; Neap's `process()` calls it on its right neighbour every sample, as Ballast calls its expanders (`src/ballast/BallastExpander.hpp`: all per-sample work inside the call).
- **Modules:** `Neap.cpp` and `Spring.cpp` map params, ports and lights onto the cores.
- **Panels:** the draft entries in `docs/plans/2026-11-24-neap-panels-draft.py`, approved by the user from the mockups (2026-11-24).

**Tech Stack:** C++11 plugin code (Rack SDK 2.6.6), C++17 offline tests with `src/testing.hpp`, the Python 3 panel generator, Inkscape.

**Spec:** `docs/specs/2026-11-24-neap-design.md`, mockups `docs/specs/2026-11-24-neap-mockup.png` and `2026-11-24-spring-mockup.png`. Testing rules: `TESTING.md`. Code to read first: `src/sway/Phasor.hpp` (double phase), `src/sway/RandomGen.hpp` (seeded glide random), `src/sway/Rate.hpp` (`expToHz`), `src/FastMath.hpp`, `src/ballast/BallastExpander.hpp` and its use in `src/ballast/Ballast.cpp` (expander threading), `src/beacon/` (a recent module end to end: engine frame/result, `bench.inc`, tests). Where this plan and the spec disagree, the spec wins; ledger the difference.

**One deliberate difference from the spec:** the spec puts Spring's code in `src/neap/`. Panels load from `res/<folder>/` with one layout header per folder, so Spring gets its own folder `src/spring/` (as Pan has beside Ballast); it includes `neap/NeapExpander.hpp`.

## Global Constraints

- **Build:** `RACK_DIR=$HOME/ws/sdk/Rack-SDK-2.6.6-mac-arm64`. Agents start Rack only through `make smoke`. Before every `make install`, `mac_dist` or `cross_build`: `tools/bump_version.sh "<what changed>"`.
- **Repo:** unit tests only; no audio or test results in the repo (they go on `/Volumes/share1/VCVRACK/`).
- **Every test is shown to fail** (a mutation, named in the ledger; `sleep 1` before the rebuild: make on macOS has 1 s timestamps). No libm per sample (`src/FastMath.hpp`); NaN-safe; no allocation or locks in `process`.
- **Neap ids** (panel, layout header, module, in this order): params `RATE`, `RATE_ATT`, `WEIGHT`, `MARK`; inputs `RATE_CV`, `WEIGHT_CV`, `RESET`; outputs `C1`..`C8`, `ALL`, `TIDE`, `HIGH` (as the draft lists them); lights `P1`..`P8`, `HIGH`. Slug `Neap`, folder `neap`, 8 HP. Tags `LFO`, `Low-frequency oscillator`.
- **Spring ids:** outputs `F1`, `F3`, `F5`, `F7`, `MIN23`, `MAX23`, `MIN67`, `MAX67`, `T2`, `T4`, `T6`, `T8`, `S14`, `S58`, `SODD`, `SEVEN`; light `LINK`. Slug `Spring`, folder `spring`, 6 HP. Tags `Expander`, `LFO`.
- **Params:** RATE 0..1, default 0.5; RATE_ATT −1..1, default 0; WEIGHT −1..1, default 0; MARK −5..5 V, default 2.
- **Steps** (cycle i to i+1, i = 1..7): 2.16, 1.93, 2.25, 1.93, 1.93, 2.23, 2.17. `L_i` = log2 of the product of the steps before cycle i (L_1 = 0).
- **Rate law:** e1 = log2(40) − 12 × (1 − RATE) + RATE_ATT × RATE_CV volts, clamped to [log2(40) − 14, log2(40) + 2]; NaN CV reads as 0. Noon e1n = log2(40) − 6. Cycle i's exponent e_i = e1 − L_i + s_i × (e1 − e1n); f_i = 2^e_i × (1 + d_i) Hz, d_i the drift (0 when Drift is off).
- **Spread slopes** s_i (starting values; the builder may retune within the rule): 0, 0.0014, 0.0011, 0.0009, 0.0004, 0.0002, 0.0008, 0.0007.
- **No-locking rule:** for every pair whose frequency ratio r ≤ 16: |r − n| / r ≥ 3 % for every integer n, and if r ≤ 6 also for every half-integer; at every e1 in the clamped range.
- **Waves:** phase p in [0, 1) as a double, starting at 0. Triangle: 4p (p < 0.25), 2 − 4p (p < 0.75), 4p − 4; sine: `fastSin2pi(p)`. Both start at 0 rising. A Wave change crossfades linearly over 10 ms. Cycle values are x_i in ±1; volts ±5 V (Level ±5) or x × 5 + 5 (Level 0–10).
- **Drift:** each cycle i has its own seeded `RandomGen` (seed 1000 + i) and a slow phasor at 1 / (60 + 9 i) Hz; d_i = 0.005 × `value(p, 1.f)`, so |d_i| ≤ 0.5 %. Advanced every sample while Drift is on.
- **RESET:** Schmitt 0.1 V / 1 V; a rising edge sets every phase to 0 (drift state is kept).
- **Tide:** w = clamp(WEIGHT + WEIGHT_CV volts / 5, −1, 1), NaN CV as 0, glided by a one-pole of 50 ms time constant. Weight of cycle i: 2^(w × (i − 4.5)). raw = G × Σ w_i x_i / Σ w_i with G = 2.0 (starting gain, tuned by ear). TIDE = 5 V × limit(raw), limit(x) = x (27 + x²) / (27 + 9 x²) for |x| < 3, else ±1. In Level 0–10 add 5 V.
- **HIGH:** 10 V when TIDE rises above MARK + 0.05 V, 0 V when it falls below MARK − 0.05 V. In Level 0–10 the mark is MARK + 5 V.
- **ALL:** 8 channels, channel i = output Ci, bit for bit.
- **Menu and saved state:** Drift (on), Wave (Triangle, Sine), Level (±5 V, 0–10 V), saved in `dataToJson` as `"drift"`, `"wave"`, `"level"`. Phases not saved; a loaded patch starts at phase 0.
- **Lights:** P_i brightness (x_i + 1) / 2 (dark at the bottom of the cycle, full at the top); HIGH lit while HIGH is high; LINK lit while linked.
- **Spring link:** Neap's `process()`, each sample, finds `rightExpander.module`, `dynamic_cast`s it to `rka::NeapExpander`, skips it if bypassed, and calls `fromNeap(const float x[8], float sampleTime)` with the **shaped** cycles in ±5 V (after Wave and crossfade, before Level). Spring does all per-sample work inside that call; its own `process()` only writes outputs and lights from the values left. Unlinked: Spring sees no `fromNeap` for 64 of its own `process()` calls (a `std::atomic<uint32_t>` counter Neap's call increments, compared in Spring's `process()`), then every output is 0 V, LINK dark and trigger state cleared.
- **Spring outputs** (from x in ±5 V): F_i = 2 |x_i| (0..10 V) for i = 1, 3, 5, 7; MIN23/MAX23 = min/max(x2, x3), MIN67/MAX67 = min/max(x6, x7); T_i a 10 ms 10 V pulse at each rising zero crossing of x_i (previous < 0 ≤ current), i = 2, 4, 6, 8; cascade: an unpatched T output's pulses go to the next patched one in the order T2 → T4 → T6 → T8 → T2, OR-merged (none patched: nothing); STEPS: bit b = (x > 0), code = 8 b_a + 4 b_b + 2 b_c + b_d for (a, b, c, d) = (1, 2, 3, 4), (5, 6, 7, 8), (1, 3, 5, 7), (2, 4, 6, 8); volts = code × 10 / 15. Spring's outputs ignore Neap's Level.
- **Rate tooltip:** "1: <period> · 8: <period>" of the actual f_1 and f_8 at that setting (spread included, drift not), period as "850 ms", "1.6 s", "4.5 min" or "4.8 h" (3 significant figures max).
- **Bypass:** Rack's default; a bypassed Neap stops calling Spring (Spring goes unlinked). **Sample rate change:** phases kept; frequencies stay in Hz.

## Review Focus

1. **RATE CV at ±10 V, huge, NaN or inf, with the attenuverter at either end:** every cycle's frequency stays finite and positive, nothing stalls or runs backwards, outputs stay in range (Tasks 2, 5).
2. **The slowest setting (cycle 8 near 19 h with CV) at 768 kHz for a long simulated run:** the double phase still advances at the right rate; no freeze or drift from rounding (Task 3).
3. **Spring added, removed, or Neap bypassed mid-run, then re-linked:** Spring falls to 0 V within 64 samples, no trigger left stuck high, and resumes cleanly with no spurious trigger burst on re-link (Tasks 6, 8).
4. **RESET held high, or driven by audio-rate noise around the thresholds:** one reset per rising edge only; no NaN; TIDE and HIGH stay coherent (Task 5).
5. **Wave toggled repeatedly, faster than the 10 ms crossfade:** no step beyond the crossfade's bound, values stay within ±1 (Task 3).
