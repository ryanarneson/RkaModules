# Squall Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Squall, an 8 HP random source of gates and CV in the Instrument look:
- **Weather** sets how much happens (from one event every 10 min to 8 a second).
- **Gust** bunches events into bursts.
- **Memory** replays the recent past.
- **Outputs:** Step, Swell and Gate, which tell one story.
- **Clocked or free-running,** with Freeze.

**Architecture:**
- **Engine:** a Rack-free `rka::SquallEngine` (`src/squall/SquallEngine.hpp`), built from small headers:
  - the event process (Weather's law and Gust's self-exciting process);
  - the memory;
  - the gate;
  - the Swell follower.
- **Module:** `Squall.cpp` only maps ports, params, menus and patch state onto the engine.
- **Panel:** the draft `"Squall"` entry already in `tools/gen_panels.py` (uncommitted, marked MOCKUP), which the user approved in conversation.

**Tech Stack:** C++11 plugin code (Rack SDK 2.6.6), C++17 offline tests with `src/testing.hpp`, the Python 3 panel generator, and Inkscape 1.4.4.

**Spec:** `docs/specs/2026-11-18-squall-design.md`, with its mockup `docs/specs/2026-11-18-squall-mockup.svg`. Testing rules: `TESTING.md`. Read the spec before any task. Where this plan and the spec disagree, the spec wins; report the difference.

## Global Constraints

- **Build:** with `RACK_DIR=$HOME/ws/sdk/Rack-SDK-2.6.6-mac-arm64`. Agents never start VCV Rack except through `make smoke`.
  - Before every build handed to the user (`make install`, mac_dist, cross_build), the controller runs `tools/bump_version.sh "<what changed>"`.
  - Before installing, the controller removes old `rka-*.vcvplugin` packages from Rack's plugins folder (#45).
- **Test results:** test results beyond unit tests, and any audio, never go in the repo. They go on `/Volumes/share1/VCVRACK/`.
- **Weather law:**
  - Position w = clamp(knob + cv/10 × att, 0, 1).
  - Free-running: rate(w) = (1/600) × 4800^w events/s. So CALM 0 is 1 per 600 s, FAIR 0.25 is about 1 per 72 s, CHANGE 0.5 is about 1 per 9 s, RAIN 0.75 is about 1 per s, and STORMY 1 is 8 per s.
  - Clocked: the chance per tick is p(w) = 256^(w − 1).
  - The default is 0.5.
- **Gust:** a self-exciting (Hawkes) process.
  - The branching ratio is n = g × N_MAX. The background rate is rate(w) × (1 − n), so the long-run rate stays rate(w).
  - Each event adds a bump of area n that decays with τ = K / rate(w). Clocked, τ is K / p(w) ticks, and the chance per tick is clamped to 1.
  - The default is g = 0.3. Starting values: N_MAX = 0.9 and K = 0.35, both tuned at the listening stop.
- **Memory:**
  - The default is m = 0.
  - Loop length L is 4, 8 (default) or 16, from a menu, saved.
  - The history holds 16 events: gap, value (0 to 1) and gate length, with gap and length stored as fractions of the average gap.
  - At each event, with probability m (and only when at least L events are stored), the next event is a replay of the one L − 1 back from the newest. It comes after its stored gap, scaled by the current average gap, with its stored value and length. Gust's process can't fire during that gap.
  - Otherwise, Gust's process times the next event, with a new value and length.
  - Every event, replayed or new, excites Gust and goes into the history.
  - Clocked, a stored gap becomes max(1, round(gap / p(w))) ticks.
  - Patching or unpatching the clock keeps the history.
- **Average gap:** free-running, 1 / rate(w). Clocked, the measured tick period / p(w). Until two clock edges have arrived, use 1 / rate(w).
- **Gate:**
  - 0 or 10 V, high for 0.25 × the average gap (replays use their stored fraction), clamped to 5 ms to 4 s.
  - An event while the gate is high drops it for 1 ms and raises it again.
  - Clocked, before two edges have arrived, the gate is 10 ms.
- **Step:** set to the event's value at each event. New values are uniform over 0 to 1.
- **Swell:**
  - A smooth follower of Step's voltage, with no overshoot and a continuous slope. Its time scales with the average gap.
  - It settles within 5 % of a held target within 2 average gaps, and gets no closer than about a third of the way in half a gap.
  - Starting design: two cascaded one-poles with ω = 2.4 / average gap.
- **Range menu** (saved, default ±5 V): ±5 V, 0 to 10 V, ±2 V and ±1 V, for Step and Swell together. Step changes at once; Swell glides.
- **Freeze** (Schmitt trigger at 0.1 V and 1 V, as is Clock):
  - While high:
    - no events, and clock edges are ignored;
    - all timers and the Gust state pause, and Step holds;
    - Swell brakes to rest over about 20 ms and holds;
    - a gate already high ends at its normal time.
  - On release, everything carries on from rest.
- **Event light:** on for 100 ms per event.
- **CV:** monophonic. A polyphonic CV uses channel 1. NaN or inf reads as 0. Attenuverters default to 0.
- **Bypass:** all outputs 0 V, gate low (none configured).
- **Saved state:** `range`, `loopLength`, `history` (count, plus up to 16 {gap, value, length}), `step` (0 to 1) and `swell` (follower state).
  - Anything non-finite or out of range loads as its default.
  - A new module starts with an empty history.
- **Engine rules:**
  - No libm per sample or per event; use `src/FastMath.hpp`, and add `fastLog2` there in Task 2.
  - No allocation in `process()`, no writable globals, denormals flushed.
  - NaN-safe comparisons, since tests build with `-funsafe-math-optimizations`.
  - Timing in doubles: a 10-minute gap at 768 kHz must not drift.
  - An unusable sample rate (non-finite, 0 or below, above 768 kHz) is ignored, keeping the last good one (48 kHz before any).
  - Plugin code is C++11.
- **Randomness:** PCG32, reusing `rka::hadal::Random` from `src/hadal/Random.hpp`. Seeded per instance on construction. No `rand()`.
- **Ids:** slug `Squall`, folder `squall`. They are pinned from Task 1:
  - params `WEATHER, GUST, MEMORY` (0–2), then `WEATHER_ATT, GUST_ATT, MEMORY_ATT` (3–5);
  - inputs `WEATHER_CV, GUST_CV, MEMORY_CV, CLOCK, FREEZE` (0–4);
  - outputs `STEP, SWELL, GATE` (0–2);
  - lights `EVENT` (0).
- **Generated files:** never hand-edit `res/`, `res-src/` or `src/squall/SquallLayout.hpp`; run `make panels`.
- **Before a task is done:** `make test`. From Task 6 on, also `make` and `make smoke`, and look at `build/screenshots/Squall.png`.

## Review Focus

1. **Audio-rate CV on Weather** (a 200 Hz square at full attenuverter). Events keep coming at the average of the two rates, nothing sticks, and the outputs stay finite (`weather_cv_audio_rate`, Task 5).
2. **The clock unpatched mid-gap while a replay is pending.** Timing carries on free-running from the same stored gap, with no stall and no burst of catch-up events (`clock_unpatch_mid_replay`, Task 5).
3. **Memory turned to 1 on a fresh module.** There are no replays until L events are stored, and no garbage values (`memory_before_full`, Task 3).
4. **Loop length changed from 16 to 4 while locked.** Replays stay in bounds and lock to the new period within L events (`loop_length_change_while_locked`, Task 3).
5. **A clock at audio rate (1 kHz) at Stormy.** The outputs stay finite, the gate gives a rising edge for each event its 1 ms retrigger allows, and nothing allocates or overflows (`fast_clock_gate`, Task 5).

### Task 2: The event process (Weather and Gust)

**Files:**
- Create: `src/squall/SquallTuning.hpp`, `src/squall/Events.hpp` and `src/squall/test_events.cpp`.
- Modify: `src/FastMath.hpp` (add `fastLog2`), `Makefile` (`MODULES += squall`) and `tests.mk` (add `build/test/squall/test_events` to `PLUGIN_MATH_TESTS`).

**Interfaces:**
- **`fastLog2`:** `inline float fastLog2(float x)` in `FastMath.hpp`, for finite x > 0, with an absolute error under 1e-3.
- **`SquallTuning.hpp`** (namespace `rka::squall`) holds every tunable in one place:
  - `N_MAX = 0.9f`, `K = 0.35f`;
  - `SWELL_OMEGA = 2.4f` (per average gap), `BRAKE_S = 0.02f`;
  - `GATE_FRACTION = 0.25f`, `GATE_MIN_S = 0.005f`, `GATE_MAX_S = 4.f`, `RETRIGGER_S = 0.001f`;
  - `FIRST_CLOCK_GATE_S = 0.01f`, `LIGHT_S = 0.1f`.
- **`Events.hpp`** (namespace `rka::squall`):
  - `inline double weatherRate(float w)`: rate(w), in events/s.
  - `inline float tickChance(float w)`: p(w).
  - `class Events`:
    - `void seed(uint32_t)`, `void setSampleRate(float fs)` (ignores bad rates), `void setWeather(float w)`, `void setGust(float g)`;
    - `bool stepFree()` advances one sample free-running and returns true when Gust's process fires;
    - `bool tick()` is one clock edge and returns true when it fires;
    - `void excite()` adds one event's bump. The engine calls it for every event, including replays.
    - `void restartWait()` begins a new wait, after a replay hands timing back.

- [ ] **Step 1: Write the failing tests** in `test_events.cpp`. Statistical runs use fs = 200 Hz, or 2 kHz at Stormy, and enough simulated time for at least 2000 events.
  - `fast_log2_accuracy`: compared with `std::log2` on 10⁴ points from 1e-9 to 1, the absolute error is under 1e-3.
  - `weather_rate_law`: weatherRate at 0, 0.25, 0.5, 0.75 and 1 is within 1e-4 relative of the formula, and rate(1) = 8.
  - `free_rate_at_each_word`: at Gust 0, the measured rate at each of the five words is within ±10 % of rate(w).
  - `gust_keeps_the_amount`: at w = 0.5, the long-run rate at Gust 0, 0.5 and 1 is within ±12 % of rate(w). Set the tolerance from measurement, at no more than 15 %.
  - `gust_clusters`: the coefficient of variation of the gaps is 1 ± 0.1 at Gust 0, and above 1.5 at Gust 1.
  - `no_pulse_at_gust_0`: the gaps pass a Kolmogorov–Smirnov test against the exponential (D < 1.63/√N), and the lag-1 to lag-10 gap autocorrelations are each under 0.05 in magnitude.
  - `clocked_chance_per_tick`: at Gust 0, the share of firing ticks is within ±10 % of p(w) at each word, and every tick fires at w = 1.
  - `long_gaps_at_calm`: at w = 0 and fs = 768 kHz, simulating 2 h (by stepping) gives a gap count consistent with rate(0) (within Poisson 3σ), and the internal time stays exact (a double accumulator).
  - `seeds_repeat_and_differ`.
- [ ] **Step 2: Run them and see them fail.** Run `make test`. Expected: compile failure. The bench guard fails until Task 7 adds `bench.inc`; that's accepted, as on Hadal.
- [ ] **Step 3: Implement.** Time is rescaled by an integrated intensity:
  - Accumulate Λ += λ / fs each sample, where λ = rate(w)(1 − n) + x.
  - The excitation x decays by exp(−1 / (τ fs)), where τ = K / rate(w). Update the coefficient every 32 samples with `fastExp2D`.
  - Fire when Λ ≥ E. Then set Λ = 0 and draw E = −ln u, using `fastLog2` with u from 32 bits in (0, 1].
  - `excite()` adds n / τ to x.
  - Clocked: each tick fires with chance clamp(p(1 − n) + x_t, 0, 1), where x_t decays per tick by exp(−p / K) and `excite()` adds n·p / K.
  - Keep state in doubles where timing depends on it.
- [ ] **Step 4: Run them and see them pass.** Run `make test`. Expected: `squall test_events: all checks passed`.
- [ ] **Step 5: Show each test can fail.** One at a time, see a test fail, then restore:
  - drop the (1 − n) factor;
  - make the wait fixed instead of exponential;
  - use float for Λ at 768 kHz;
  - stop `excite()` adding;
  - use rate(w) instead of p(w) for the clocked chance.
- [ ] **Step 6: Commit:** "Squall: event process (Weather, Gust)".

    - `light_on_each_event`: the light rises on each event and lasts 100 ms.
  - **Memory:**
    - `memory_zero_no_repeat`: at m = 0, lag-L value matches are at chance (fewer than 1 % equal).
    - `memory_one_exact_loop`: at m = 1, after L events, the values and gate rises are exactly periodic in events, and the gaps repeat to within one sample.
    - `memory_share`: at m = 0.7, the share of replays is 0.7 ± 0.05 over 5000 events (counted through a test-visible counter).
    - `replay_owns_timing`: during a replayed gap, Gust's process never fires (counted through a test-visible counter).
    - `locked_loop_scales_with_weather`: with m = 1 and the loop locked, moving w from 0.5 to 0.75 shortens the gaps by rate(0.5)/rate(0.75) within 2 %, and the values are unchanged.
  - **Clock and Freeze:**
    - `clocked_events_on_edges_only`.
    - `clocked_gate_uses_tick_period`.
    - `clocked_first_gate_10ms`.
    - `clock_unpatch_mid_replay` (Review Focus 2).
    - `history_survives_clock_change`.
    - `fast_clock_gate` (Review Focus 5).
    - `freeze_holds`: no events, Step constant, Swell brakes then holds, and a high gate ends at its time.
    - `freeze_resumes`: after release, the time left in the pending wait is the same as before Freeze.
  - **CV and state:**
    - `weather_cv_audio_rate` (Review Focus 1).
    - `state_round_trip`: getState then setState on a fresh engine continues identically.
    - `state_rejects_bad`: NaN, a count of 17 and out-of-range values load as defaults.
    - `bad_rate_ignored`: 0, −1, NaN, inf and 1e9 are ignored.
    - `seeds_differ_and_repeat`.
- [ ] **Step 2: Run them and see them fail.**
- [ ] **Step 3: Implement the engine.**
  - **Every 32 samples:** read the controls with the CV law, then set the weather, gust, average gap and Swell gap.
  - **Each sample:**
    - Run the Schmitt triggers for Clock and Freeze.
    - Unless frozen, advance the timing. A pending replay counts down in average-gap units free-running (by rate/fs per sample), or in ticks when clocked. Otherwise Gust's process runs.
    - **On an event:**
      - Record the gap since the last one, in average gaps.
      - Set Step, fire the gate and the light, excite Gust, and push to memory.
      - Decide the next event: replay with chance m when `canReplay()`, otherwise call `restartWait()`.
    - Map Step to the range, then run Swell and the gate.
  - **When the clock is patched or unpatched,** convert a pending replay's countdown between ticks and average gaps.
- [ ] **Step 4: Run them and see them pass.**
- [ ] **Step 5: Show each test can fail.** One at a time:

  - make replays not excite;
  - store gaps in seconds;
  - skip the clamp on the gate length;
  - drop the Freeze pause of the wait;
  - drop the state validation.
