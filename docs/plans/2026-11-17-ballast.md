# Ballast Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ballast, a 12 HP four-channel stereo mixer in the Instrument look.
- Each channel: a Level knob and a VCA-law level CV.
- A master knob with its own CV.
- CHAIN inputs.
- A DC-blocked, soft-limited stereo out with a CLIP light.
- An expander connection that the Pan expander (next) builds on.

**Architecture:**
- **Engine:** a Rack-free `rka::BallastEngine` (`src/ballast/BallastEngine.hpp`) does the whole signal path.
- **Expanders:** `rka::BallastExpander` (`src/ballast/BallastExpander.hpp`) is the interface an expander implements. The engine calls it at three points in the path.
- **Module:** `Ballast.cpp` maps params, ports and the menu onto the engine. On every sample it walks the expanders to its right and hands them to the engine.
- **Panel:** the `"Ballast"` entry in `tools/gen_panels.py` (now an uncommitted draft marked MOCKUP), finished.

**Tech Stack:** C++11 plugin code (Rack SDK 2.6.6), C++17 offline tests with `src/testing.hpp`, the Python 3 panel generator, and Inkscape 1.4.4.

**Spec:** `docs/specs/2026-11-17-ballast-design.md`, with its mockup `docs/specs/2026-11-17-ballast-mockup.png`. Testing rules: `TESTING.md`. Read the spec before any task. Where this plan and the spec disagree, the spec wins; report the difference.

## Global Constraints

- **Build:** with `RACK_DIR=$HOME/ws/sdk/Rack-SDK-2.6.6-mac-arm64`. Agents never start VCV Rack except through `make smoke`.
  - Before every `make install`, `mac_dist` or `cross_build`, the controller runs `tools/bump_version.sh "<what changed>"`.
- **Test results:** test results beyond unit tests, and any audio, never go in the repo. They go on `/Volumes/share1/VCVRACK/`.
- **Knob curve:** gain = 2 × p^2.41, with p in [0, 1]. p = 0 is silence, 0.75 is unity (0 dB), 1 is +6 dB. Every Level and Master defaults to 0.75. The tooltip shows dB.
- **Level CV (VCA law):** gain = knob gain × clamp(CV / 10 V, 0, 1), linear in CV.
  - An unpatched CV reads 10 V.
  - A polyphonic CV uses channel 1.
  - CV is **not** smoothed.
- **Knob smoothing:** a one-pole of about 10 ms on the knob position. It snaps to the current value on the first sample after construction, reset or a sample-rate change.
- **Inputs:**
  - IN R is normalled to IN L. A channel is **mono** when IN L is patched and IN R is not.
  - Polyphonic inputs, CHAIN included, are summed.
  - CHAIN L and R are added at unity before Master. CHAIN R is normalled to CHAIN L.
- **Outputs:**
  - Per side, in order: mix, Master (with its CV), DC blocker (if on), soft limit.
  - With R unpatched, L = (L + R) / √2, crossfaded over 10 ms. R alone is the right side only.
  - Outputs are monophonic.
- **DC blocker:** a one-pole high-pass at 3 Hz, coefficient set on a rate change. It is on by default and saved as the JSON key `dcBlock`; a patch without the key loads with it on.
- **Soft limit:** Ballast's own copy of Hadal's curve: knee 8 V, ceiling 10 V, `fastTanh`.
- **CLIP light:** lit while either output is above the knee, held for 150 ms.
- **No work** when neither output is patched.
- **Bypass** silences both outputs (no bypass routes).
- **Expanders:**
  - They are read at the same sample, by walking `rightExpander` in `process()`. The walk stops at the first module that is not a `rka::BallastExpander`, and nothing is cached across samples.
  - With no expander, Ballast's output is bit-identical, and the CPU stays within the bench.
- **Engine rules:**
  - no libm per sample (`src/FastMath.hpp`; the curve comes from a table built on construction), no allocation in `process()`, no writable globals, denormal-safe;
  - NaN and inf become 0 where they enter, using NaN-safe comparisons;
  - plugin code is C++11.
- **The libm check:** before Tasks 2–5 close, run it on Linux in the toolchain image, because it is skipped on the Mac (issue #36):
  `docker run --rm --platform linux/amd64 -v <copy>:/w ghcr.io/bloodbat/rack-plugin-toolchain-win-linux bash -c "cd /w && make -f tests.mk libm-calls CXX=g++"`. Use a `git ls-files` copy of the tree under `$HOME`.
- **Generated files:** never hand-edit `res/`, `res-src/` or `src/ballast/BallastLayout.hpp`. Run `make panels`.
- **Ids:** slug `Ballast`, folder `ballast`. They are pinned from Task 1:
  - params `LEVEL_1, LEVEL_2, LEVEL_3, LEVEL_4, MASTER` (0–4);
  - inputs `IN_1L, IN_1R, IN_2L, IN_2R, IN_3L, IN_3R, IN_4L, IN_4R` (0–7), then `CV_1 … CV_4` (8–11), `MASTER_CV` (12), `CHAIN_L` (13), `CHAIN_R` (14);
  - outputs `L, R` (0–1);
  - lights `CLIP` (0).
- **Before a task is done:** `make test`. From Task 6 on, also `make` and `make smoke`, and look at `build/screenshots/Ballast.png`.

## Review Focus

1. **R patched or unpatched while playing.** L switches between the mono sum and the left side with no click (`mono_normal_switch_no_click`, Task 2).
2. **Audio-rate CV**, a 1 kHz sine from 0 to 10 V. The output equals input × knob gain × CV / 10 on every sample, with no slew (`cv_not_smoothed`, Task 2).
3. **Hot everything.** Four channels at ±10 V, CHAIN at ±10 V, and every knob at +6 dB: the output stays finite, |out| ≤ 10 V, and CLIP is lit (`hot_inputs_bounded`, Task 3).
4. **An expander attached or removed between two samples.** No NaN and no lasting change; after removal the output is bit-identical to an engine that never had one (`expander_attach_detach`, Task 4).
5. **Sixteen-channel polyphonic inputs and CV.** Inputs are summed, and the CV uses channel 1 (`poly_inputs_summed`, `poly_cv_uses_channel_1`, Task 2).

### Task 2: The engine: curve, VCA law, normals, mix, master, mono out

**Files:**
- Create: `src/ballast/BallastEngine.hpp`, `src/ballast/BallastExpander.hpp` (the interface only; Task 4 tests it) and `src/ballast/test_engine.cpp`.
- Modify: `tests.mk` (add `build/test/ballast/test_engine` to `PLUGIN_MATH_TESTS`).

**Interfaces (namespace `rka`):**
- `struct BallastPort { const float* v = nullptr; int channels = 0; float sum() const; float first() const; }`:
  - `sum()` adds every channel, with NaN and inf read as 0;
  - `first()` is channel 1, or 0.
- `struct BallastFrame`:
  - `enum { LEVEL_1, LEVEL_2, LEVEL_3, LEVEL_4, MASTER, PARAMS_LEN };`
  - `float params[PARAMS_LEN];`
  - `BallastPort inL[4], inR[4], cv[4], masterCv, chainL, chainR;`
  - `bool outL = false, outR = false, dcBlock = true;`
- `struct BallastResult { float l = 0, r = 0; bool clip = false; };`
- `struct BallastExpander`, with each default doing nothing:
  - `virtual void preLevel(int ch, float& l, float& r)`;
  - `virtual void postLevel(int ch, float& l, float& r, bool mono)`;
  - `virtual void intoMix(float& l, float& r)`;
  - `virtual ~BallastExpander()`.
- `class BallastEngine`:
  - `BallastEngine()`;
  - `void setSampleRate(float fs)` ignores rates that are not finite, ≤ 0 or above 768 kHz;
  - `void reset()`;
  - `void process(const BallastFrame& f, BallastResult& out, BallastExpander* const* chain = nullptr, int chainLen = 0)`;
  - `static float curveExact(float p)`, i.e. 2·p^2.41 with libm, for tests only;
  - `float curve(float p) const`, the table (257 points, linear interpolation);
  - the test hook `long work() const`, the count of samples processed.

- [ ] **Step 1: Write the failing tests** in `test_engine.cpp`:
  - **The curve:**
    - `curve_points`: `curve(0) == 0`; `curve(0.75)` is 0 dB within 0.01; `curve(1)` is +6.02 dB within 0.01; monotonic over 1001 points; within 0.05 dB of `curveExact` wherever `curveExact > 1e-3`.
  - **The VCA law:**
    - `vca_law`: one channel, a DC input of 1 V on IN L, DC blocker off, both outputs patched; read `out.l`. Check:
      - an unpatched CV gives the knob's gain;
      - 0 V and −3 V give 0;
      - 5 V gives −6.02 dB ± 0.01 under the knob;
      - 10 V and 12 V give the knob's gain;
      - no CV ever exceeds the knob.
    - `master_cv_law`: the same checks on Master.
    - `cv_not_smoothed`: a 1 kHz sine CV from 0 to 10 V with a DC input. Each sample equals input × knob gain × CV/10 within 1e-5.
    - `poly_cv_uses_channel_1`.
  - **Normals and mixing:**
    - `normals`: IN R is normalled to IN L; IN R alone leaves L silent; CHAIN R is normalled to CHAIN L.
    - `poly_inputs_summed`: 16 channels of 0.1 V each read as 1.6 V.
    - `mix_sum`: four channels and CHAIN add on each side, and Master scales the total, CHAIN included.
    - `mono_normal`: with R unpatched, L = (L + R)/√2. With R patched, L is the left side and R the right.
    - `mono_normal_switch_no_click`: on a 100 Hz sine, the largest step at the switch is at most 2× the steady largest step plus 0.01 V.
  - **Smoothing and idle:**
    - `knob_smoothing`: a Level step from 0.75 to 0 makes no output step larger than 5 % of the input, and settles to under −60 dB within 100 ms. The first sample after construction already uses the knob's value (no fade-in).
    - `nothing_patched_no_work`: `work()` does not advance while neither output is patched, and the outputs are 0.
- [ ] **Step 2: Run them and see them fail** (`make build/test/ballast/test_engine && ./build/test/ballast/test_engine`).
- [ ] **Step 3: Implement** the engine and the interface header.
  - Signal path: per channel, preLevel hooks, then Level × CV, then postLevel hooks; then the sum, CHAIN, intoMix hooks, Master, and the mono normal.
  - For this task, the DC blocker and the limit are pass-through stubs.
- [ ] **Step 4: Run them and see them pass.**
- [ ] **Step 5: Show each test can fail.** One at a time: use a linear curve, additive CV, a smoothed CV, no mono normal, and no knob smoothing. See a test fail each time, then restore.
- [ ] **Step 6:** Run the Linux libm check (Global Constraints). Expected: `ballast` is not in the bench yet, so the check runs clean. **Commit:** "Ballast: engine".

### Task 3: The output stage: DC blocker, soft limit, CLIP

**Files:**
- Modify: `src/ballast/BallastEngine.hpp` and `src/ballast/test_engine.cpp`.

**Interfaces:**
- **Produces:** the test hook `long limited() const`, the count of samples the limit acted on.

- [ ] **Step 1: Write the failing tests:**
  - **The DC blocker:**
    - `dc_blocker`: a 1 V DC input falls below 1 mV within 1 s. A 30 Hz sine loses under 0.1 dB. A 3 Hz sine is −3 dB ± 0.5.
    - `dc_blocker_off`: with `dcBlock = false`, DC passes exactly.
  - **The soft limit:**
    - `limit_curve`: a 7.9 V DC input with the blocker off passes untouched (`limited()` stays 0). 30 V reads at or below 10 V. The curve is continuous at 8 V.
    - `hot_inputs_bounded`: every input at ±10 V square waves, CHAIN too, and every knob at full. The output is finite, |out| ≤ 10 V, and `clip` is true.
  - **The CLIP light:**
    - `clip_hold`: one sample above 8 V lights `clip` for 150 ms ± 1 sample at 48 kHz, then it goes dark.
    - `defaults_never_limit`: one channel with a 5 V-peak sine, every knob at its default: `limited()` stays 0.
- [ ] **Step 2: Run them and see them fail.**
- [ ] **Step 3: Implement.**
  - The DC blocker is a one-pole high-pass at 3 Hz per side. Its coefficient is set in `setSampleRate`, with `std::exp` allowed there.
  - The limit is copied from `HadalEngine::limit`.
  - The CLIP hold counts samples.
- [ ] **Step 4: Run them and see them pass.**

### Task 4: The expander hook

**Files:**
- Create: `src/ballast/test_expander.cpp`.
- Modify: `tests.mk` and, only if a test shows a defect, `BallastEngine.hpp`.

**Interfaces:**
- **Consumes:** `BallastExpander` and the `process(..., chain, chainLen)` overload from Task 2.
- **Produces, for the Pan expander:** the contract as documented in `BallastExpander.hpp`'s header comment:
  - the call order;
  - `mono` as defined;
  - `ch` from 0 to 3;
  - every call happens on the same sample.

- [ ] **Step 1: Write the failing tests** with a test-only stand-in, `struct Gain : rka::BallastExpander`, which applies a fixed gain or offset at whichever stage the test chooses:
  - **Same sample:**
    - `post_level_same_sample`: a ×0.5 postLevel on channel 1 halves that channel's contribution on the very same sample, with no lag.
    - `pre_level_before_level`: a +1 V preLevel offset is scaled by Level and CV, and a postLevel one is not.
    - `into_mix_before_master`: an intoMix addition is scaled by Master.
  - **Contract and order:**
    - `mono_flag`: `mono` is true only with IN L patched and IN R not.
    - `chain_order`: two stand-ins, ×2 then +1, give (x·2)+1, not (x+1)·2.
  - **No cost when absent:**
    - `no_expander_bit_identical`: `process(f, r)` and `process(f, r, nullptr, 0)` match bit for bit over 10 s of noise. So does a chain of one stand-in that does nothing (unity).
    - `expander_attach_detach`: attach, then detach, between samples. No NaN, and after the detach the output matches a fresh engine fed the same input bit for bit.
- [ ] **Step 2: Run them.** Expected: those that pass on Task 2's code pass. Show each can fail by mutation: call postLevel before Level, skip intoMix, reverse the chain, and set `mono` wrong. If any fails on the real code, fix the engine.
- [ ] **Step 3:** Run the Linux libm check. **Commit:** "Ballast: expander hook tests".
