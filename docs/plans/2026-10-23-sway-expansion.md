# Sway Expansion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move all code under `src/`, fix Sway's slow-rate phase stall, and grow Sway into an 18 HP LFO with clock sync, phase spread, shaping, random outputs, ranges, hold/one-shot and CV with attenuverters.

**Architecture:** Small Rack-free DSP headers in `src/sway/` (Rate, Phasor, Waves, ClockSync, Shaper, RandomGen), each unit-tested offline; `src/sway/Sway.cpp` only maps params/ports/polyphony onto them. Panel geometry stays generated by `tools/gen_panels.py`.

**Tech Stack:** C++11 for the plugin (Rack SDK 2.6.6 `plugin.mk`), C++17 for offline tests, Python 3 + Inkscape for panels, VCV Rack 2 for `make smoke`.

**Spec:** `docs/specs/2026-10-23-sway-expansion-design.md` (read it first; this plan does not repeat its tables).

## Global Constraints

- Plugin slug `rka`, module slug `Sway`, version stays `2.0.0` (unreleased).
- Plugin code must compile as C++11 (`plugin.mk`); `src/testing.hpp` and `test_*.cpp` may use C++17.
- DSP headers in `src/sway/*.hpp` (except `SwayLayout.hpp`) must not include `rack.hpp`.
- Never hand-edit `res/`, `res-src/`, `src/*/*Layout.hpp`, `src/RkaTheme.hpp`; run `make panels`.
- Voltages: outputs ±5 V (BI) or 0–10 V (UNI); triggers/gates via `SchmittTrigger` at 0.1 V / 1 V; FM 1 V/oct at full attenuverter.
- Use `rka::` widgets from `src/widgets.hpp`, never stock knobs, in modules.
- Tools stay portable (macOS + Linux): no `sed -i`, no GNU-only flags.
- Every shell needs `RACK_DIR=$HOME/ws/sdk/Rack-SDK-2.6.6-mac-arm64` (non-interactive shells don't read `~/.zshrc`).
- Done per task: `make test` passes; for tasks touching the plugin also `make` with no warnings and `make smoke` prints `ok: Sway`.

## Review Focus

1. SKEW at exactly 0 or 1 → finite output, no division by zero (test in Task 5).
2. CLOCK cable removed mid-run → Sway immediately runs free from RATE, no stale period (test in Task 4 + `clear()` call in Task 8).
3. 1-SHOT turned off while parked → LFO resumes running (test in Task 2).
4. Fast clock × high ratio or Audio range + FM → frequency clamped to 0.45 · sample rate (test in Task 2, used for clocked frequency in Task 8).
5. Step larger than one cycle (`freq · dt > 1`) → phase still lands in [0, 1) (test in Task 2).

### Task 2: Rate, Phasor, Waves — fix the slow-rate stall

Replaces `LfoCore.hpp` with three headers; Sway keeps today's panel and behaviour except the bug is gone.

**Files:**
- Create: `src/sway/Rate.hpp`, `src/sway/Phasor.hpp`, `src/sway/Waves.hpp`, `src/sway/test_phasor.cpp`, `src/sway/test_waves.cpp`
- Delete: `src/sway/LfoCore.hpp`, `src/sway/test_lfo_core.cpp` (move its still-relevant checks: frequency/rate mapping, tri continuity, pulse width, sin/tri in phase, reset, huge step, volts, into the new tests)
- Modify: `src/sway/Sway.cpp`

**Interfaces (namespace `rka`):**
- `enum Range { RANGE_SLOW = 0, RANGE_NORMAL = 1, RANGE_AUDIO = 2 };`
- `float rateExponent(float rate, float fm, Range range)` → log2(Hz): Slow `rate - 7 + fm`; Normal `rate + fm`; Audio `log2(261.6256) + rate * 5/7 + fm`.
- `double expToHz(float exponent, float sampleRate)` → `exp2(clamp(exponent, -24, 14))`, then `min(…, 0.45 * sampleRate)`.
- `double clampHz(double hz, float sampleRate)` → `min(hz, 0.45 * sampleRate)` (used for clocked frequencies).
- `float lfoVolts(float x, bool unipolar)` (unchanged).
- `struct Phasor { double phase = 0; bool parked = false; void reset(); void park(); bool step(double freq, double dt, bool hold, bool oneShot); }`
  - `PARK_PHASE = 1.0 - 1e-9` (so SAW reads ≈ +1, SIN/TRI ≈ 0 when parked).
  - `step`: if `!oneShot` clear `parked`; if `hold || parked` return false; advance; on reaching ≥ 1 either park (oneShot) or `phase -= floor(phase)`; return true on wrap.
  - `reset()`: phase 0, parked false. `park()`: phase `PARK_PHASE`, parked true.
- Waves (phase `p` in [0, 1), output [-1, 1]): `float waveSin(float p)`, `waveTri(float p)`, `waveSaw(float p)`, `waveSqr(float p, float pw)` — same shapes as `LfoCore` today. `float polyBlep(float t, float dt)` (standard 2-sample polyBLEP residual), `float sawBlep(float p, float dt)`, `float sqrBlep(float p, float pw, float dt)`; with `dt == 0` they equal the naive waves.

- [ ] **Step 1: Write failing tests** in `test_phasor.cpp`:
  - `testSlowPeriods`: for exponents −7 and −14 at 48 kHz, measured period between two wraps within 0.1% of `1/f`.
  - `testNoStallAtMinRate`: at 2⁻²⁴ Hz, after 10⁶ steps the phase has increased by `10⁶ · f / 48000` within 1%.
  - `testHugeStep`: `step(30000, 1/48000.)` repeatedly keeps phase in [0, 1).
  - `testHold`: `hold=true` leaves phase unchanged and returns false.
  - `testOneShotParks`: oneShot run for 1.5 cycles → `parked`, `phase == PARK_PHASE`, wrapped exactly once.
  - `testOneShotOffResumes`: after parking, `step(..., oneShot=false)` advances again (Review Focus 3).
  - `testRateExponent`: Normal(1, 0) = 1; Slow(−7, 0) = −14; Audio(0, 0) = log2(261.6256); Normal(0, 1) = 1.
  - `testClamps`: `expToHz(-40, 48000) == exp2(-24)`; `expToHz(20, 48000) == 0.45 * 48000`; `clampHz(1e6, 44100) == 0.45 * 44100` (Review Focus 4).
  In `test_waves.cpp`: the old tri continuity, pulse width, sin/tri in phase and volts checks against the new functions, plus `testBlepIdentityAtZeroDt` and `testBlepReducesAliasing` (5 kHz saw at 48 kHz, 4096 samples: sum of |y[n] − y[n−1]|² over the naive saw exceeds that of `sawBlep` — a cheap proxy for high-frequency energy).

- [ ] **Step 2: Run** `make test` → Expected: compile errors (headers missing).

- [ ] **Step 3: Implement** the three headers per Interfaces.

- [ ] **Step 4: Run** `make test` → Expected: `test_phasor` and `test_waves` pass.

### Task 4: ClockSync

**Files:** Create `src/sway/ClockSync.hpp`, `src/sway/test_clock_sync.cpp`.

**Interfaces:**
- `static const float CLOCK_RATIOS[15] = {1/16., 1/12., 1/8., 1/6., 1/4., 1/3., 1/2., 1, 2, 3, 4, 6, 8, 12, 16};`
- `int ratioIndex(float rate, float fm)` → `clamp(round(rate + fm), -7, 7)`; `float clockRatio(int index)` → `CLOCK_RATIOS[index + 7]`.
- `struct ClockSync { bool process(bool edge, double dt, int index); bool locked() const; double frequency(int index) const; void resetCount(); void clear(); }`
  - Tracks time since last edge; on each edge after the first, `period = elapsed`. `locked()` once two edges have been seen.
  - `process` returns true (resync now) only when locked and: ratio ≥ 1 → every edge; ratio < 1 → every N-th edge (`N = round(1/ratio)`), counter cleared by `resetCount()`.
  - `frequency(index) = clockRatio(index) / period`.
  - `clear()`: forget edges/period/count (unlocked).

- [ ] **Step 1: Failing tests** (synthetic 120 BPM clock = edge every 0.5 s at 48 kHz):
  - `testUnlockedBeforeTwoEdges`.
  - `testTimesFour`: index for ×4 → `frequency == 8 Hz` (1e-3), resync on every edge.
  - `testDivideFour`: ÷4 → `0.5 Hz`, resync on edges 4, 8, 12 only.
  - `testResetCount`: after `resetCount()` the next resync is 4 edges later.
  - `testClearUnlocks` (Review Focus 2): after `clear()`, `locked()` is false until two new edges.
  - `testRatioIndexClamps`: `ratioIndex(7, 3) == 7`, `ratioIndex(-7, -3) == -7`, `ratioIndex(0.4, 0) == 0`.
  - `testPhasorLocks`: drive a `Phasor` with `frequency()` and reset it on each resync; at ×4 the phase at each clock edge (before reset) is within 0.01 of 0 or 1.

### Task 5: Shaper

**Files:** Create `src/sway/Shaper.hpp`, `src/sway/test_shaper.cpp`.

**Interfaces:**
- `float skewPhase(float p, float skew)` — clamp skew to [0.001, 0.999]; `s = frac(p + 0.25)` (0 at the trough); `w = s < skew ? 0.5 * s / skew : 0.5 + 0.5 * (s - skew) / (1 - skew)`; return `frac(w - 0.25)`.
- `float shape(float p, float skew, float morph, float smooth, float pw, float dt)`:
  1. `q = skewPhase(p, skew)`.
  2. Morph: `m = clamp(morph, 0, 1) * 3`, segment `k = min(int(m), 2)`, crossfade waves `[sin, tri, saw, sqr]` k → k+1 by `m - k`; saw/sqr use `sawBlep`/`sqrBlep` with `dt` scaled by the local warp slope (`0.5/skew` before the peak, `0.5/(1-skew)` after).
  3. Smooth < 0: `y = lerp(y, sin(π/2 · y), -smooth)`. Smooth > 0: `y = fold(y * (1 + 3 * smooth))` with `fold(x) = 1 - |mod(x + 1, 4) - 2|` (positive mod).

- [ ] **Step 1: Failing tests:**
  - `testPureShapes`: with skew 0.5, smooth 0, dt 0: morph 0/⅓/⅔/1 equal `waveSin/Tri/Saw/Sqr(p, pw)` at 100 phases (1e-5).
  - `testSkewIdentity`: `skewPhase(p, 0.5) == p` (1e-6).
  - `testSkewRamps`: skew 1 and morph ⅓ (tri) is monotonic rising over (0.75, 1.75) wrapped; skew 0 is monotonic falling.
  - `testSkewExtremesFinite` (Review Focus 1): skew exactly 0 and 1, all morphs, 1000 phases → `std::isfinite` and in [-1, 1].
  - `testSmoothZeroIdentity`, `testFoldInRange` (smooth 1, any y → [-1, 1]), `testFoldFolds` (tri at smooth 1 has more than 2 local maxima per cycle).
- [ ] **Step 2: Run** → FAIL. **Step 3: Implement.** **Step 4: Run** → PASS.
