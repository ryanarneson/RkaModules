# Narrows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Narrows, a 14 HP polyphonic stereo filter in the Instrument look: low-pass, band-pass and high-pass on a smooth Mode sweep, two cores on a switch (Fathom's ladder and a state-variable filter), drive, resonance to self-oscillation in tune, a comb tuned to Cutoff, a Ping input and Spread.

**Architecture:**
- **Shared:** `src/Float4.hpp`, four floats side by side on the compiler's vector type. The ladder's stage maths and the halfband all-pass cascade become templates on the sample type; Fathom uses them with `float`, bit-identical to today.
- **Engine:** a Rack-free `rka::NarrowsEngine` (`src/narrows/NarrowsEngine.hpp`) built from small headers: the control laws, the state core, the comb, the ping pulse. Voices go through the cores four sides at a time: one pass holds the left and right of two voices.
- **Module:** `Narrows.cpp` only maps ports, params and channel counts onto the engine.
- **Panel:** the draft `"Narrows"` entry kept at `docs/plans/2026-11-20-narrows-panel-draft.patch`. It no longer applies with `git apply` (Wake's entry landed after it); insert its `_NR_X` line and its entry by hand, then delete the file in Task 1.

**Tech Stack:** C++11 plugin code (Rack SDK 2.6.6), C++17 offline tests with `src/testing.hpp`, the Python 3 panel generator, Inkscape.

**Spec:** `docs/specs/2026-11-20-narrows-design.md`, mockup `docs/future/narrows-mockup.png`. Testing rules: `TESTING.md`. Code to read first: `src/fathom/Ladder.hpp`, `Halfband.hpp`, `Svf.hpp`, `test_ladder.cpp`; `src/sluice/SluiceEngine.hpp` (a frame with per-channel ports); `src/wake/WakeEngine.hpp` (control smoothing, the output limit, L alone as the average) and `src/wake/Wake.cpp` (allocation on a rate change, bypass); `src/DelayLine.hpp`; `src/FastMath.hpp`. Read the spec before any task. Where this plan and the spec disagree, the spec wins; ledger the difference.

## Global Constraints

- **Build:** `RACK_DIR=$HOME/ws/sdk/Rack-SDK-2.6.6-mac-arm64`. Agents start Rack only through `make smoke`. Before every `make install`, `mac_dist` or `cross_build`: `tools/bump_version.sh "<what changed>"`, and clear older `rka-*` packages from Rack's plugins folder (#45).
- **Repo:** unit tests only; no audio, no test results beyond unit tests (they go on `/Volumes/share1/VCVRACK/`).
- **Every test is shown to fail** (a mutation, named in the ledger; remove the test binary before the rebuild). No libm per sample (`src/FastMath.hpp`, `tan34`); NaN-safe; no allocation in `process`.
- **Fathom does not change:** its `Ladder` and halfband keep their interfaces and give bit-identical output.
- **Ids** (panel, layout header, module, in this order): params `CUTOFF`, `DRIVE`, `FM`, `RES`, `COMB`, `SPREAD`, `CORE`, `MODE`; inputs `VOCT`, `FM_CV`, `RES_CV`, `COMB_CV`, `PING`, `L`, `R`, `MODE_CV`; outputs `L`, `R`; no lights. Slug `Narrows`.
- **Scale:** inside, 10 V is 1.0. Out is ×10, then a soft limit with its knee at 8 V and its ceiling at 10 V (the curve of Wake's outputs), after the downsampler.
- **Cutoff:** knob k in 0..1, f = 16 Hz × 2^(10k); default k = 0.6. Per voice and side: octaves = 10k + V/OCT + FM volts × FM knob ± Spread; f held to 8 Hz .. min(20 kHz, 0.45 fs). FM knob −1..1, default 0. Worked out every sample; the knob is smoothed over about 5 ms, the jacks are not.
- **Spread:** s in 0..1, default 0: left −s/2 octave, right +s/2 octave. At 0, the same input gives left = right to the bit.
- **Core:** 0 Ladder (default), 1 State. Both run at 2× through the halfband pair. A change crossfades over about 30 ms; only the selected core runs outside the fade; the incoming core is kicked so a self-oscillating voice is back within 3 dB inside 100 ms (at 100 Hz and above).
- **Mode:** m = clamp(knob + volts / 10, 0, 1), default 0; LP at 0, BP at 0.5, HP at 1, straight blends between. State: weights on lp, bp, hp. Ladder: weights on (u, y0, y1, y2, y3) between (0, 0, 0, 0, 1), (0, 0, 4, −8, 4) and (1, −4, 6, −4, 1); the passband make-up is 1 + k × (the low-pass weight). Smoothed over about 5 ms.
- **Res:** r = clamp(knob + volts / 10, 0, 1), default 0. Ladder feedback 4.1 × r². The state core self-oscillates from the same r (within 0.01). Low-pass passband unity at any r, in both cores.
- **Self-oscillation:** within 5 cents of the cutoff from 30 Hz to 4 kHz at onset, within 15 cents up to r = 1, at 44.1 kHz and above; 4 to 9 V peak; the two cores within 3 dB of each other. The noise that starts it is one stream per voice, shared by both sides.
- **Drive:** d in 0..1, default 0: a gain of 2^(4d) into the core, with make-up after it so a 5 V passband sine stays within 6 dB of its Drive 0 level. At d = 0, r = 0: a 5 V passband sine is within 1 dB of the small-signal gain with under 3 % distortion.
- **Comb:** c = clamp(knob + volts / 5, −1, 1), knob −1..1, default 0. Feedback up to ±0.95; delay = one period of that side's cutoff, at least 2 samples, slid over a few milliseconds when it jumps. A peak comes out no more than about 6 dB above dry. At c = 0 exactly the signal is bit-exact and the delay is still written.
- **Ping:** rising edge 0.1 V / 1 V; one smooth hump of about 1 ms and 5 V (0.5 inside) into both sides of the voice, before the comb.
- **Voices:** count = max(1, channels of IN L, IN R, V/OCT, PING), at most 16. A one-channel cable (audio, V/OCT, PING or CV) feeds every voice; a polyphonic one gives 0 V past its last channel. IN L alone feeds both sides, and IN R alone likewise. Outputs carry one channel per voice; with R unpatched, L is (L + R) / 2 per voice. Voice n's output does not depend on the other voices.
- **Input:** held to ±24 V; NaN and inf read 0. **Bypass:** IN L to L, IN R to R, all channels, same normalling. **Saved:** params only. **Initialize** and a rate change bring every voice to rest.
- **Rows** on the panel at 64, 83, 102 and 116 mm; columns 7.8, 21.7, 35.56, 49.4, 63.3 mm.

## Review Focus

1. **Channel counts that disagree or change every sample** (16 on IN L, 3 on IN R, 1 on V/OCT; 16 → 1 → 5): no NaN, no click in the voices that remain, unused lanes stay quiet and cheap. (Task 6, Task 7.)
2. **Cutoff at its ends with ±10 V audio-rate FM, at 44.1 to 768 kHz:** the tangent stays inside its domain, the comb's delay stays inside its buffer and at 2 samples or more, tuning does not fold. (Task 5, Task 6, Task 7.)
3. **Res, Comb and Drive at their tops for minutes with DC, silence or loud noise in:** within ±10 V, no DC building, no denormal slowdown, and the ring dies away once Res comes down. (Task 6, Task 7.)
4. **The core switch flipped every few samples, and Mode's CV at audio rate:** no click storm, no stuck fade, bounded cost. (Task 6, Task 7.)
5. **PING at audio rate, held high, or polyphonic over a mono audio cable:** one pulse per edge, each voice from its own channel, bounded level. (Task 5, Task 6.)

```cpp
namespace rka {
typedef float Float4 __attribute__((vector_size(16)));
inline Float4 splat4(float x);
// The same names for one float and for four, so a template reads the same.
// vmax(a, b) is std::max(a, b) for float: the argument order matters for
// bit-identity with today's Ladder.hpp.
inline float vmin(float a, float b);   inline Float4 vmin(Float4 a, Float4 b);
inline float vmax(float a, float b);   inline Float4 vmax(Float4 a, Float4 b);

// src/fathom/Halfband.hpp
template <typename T> T allpassCascade(T x, T* state, const float* coef, int sections);
template <typename T> struct Upsampler2xT   { void reset(); void process(T in, T out[2]); };
template <typename T> struct Downsampler2xT { void reset(); T process(const T in[2]); };
typedef Upsampler2xT<float> Upsampler2x;  typedef Downsampler2xT<float> Downsampler2x;

// src/fathom/LadderCore.hpp
template <typename T> T tan34(T x);
template <typename T> T tanhXdX(T x);
template <typename T> struct LadderNodes { T u, y0, y1, y2, y3; };   // u is the clamped loop input
template <typename T> struct LadderCore {
	void reset();
	// One oversampled-rate sample. g: per-pole tan; k: feedback; comp: input
	// gain; noise: this sample's term, already scaled.
	LadderNodes<T> step(T x, T g, T k, T comp, T noise);
};
template <typename T> T ladderLimit(T v);   // v * tanhXdX(v / 2): +/-2
```
