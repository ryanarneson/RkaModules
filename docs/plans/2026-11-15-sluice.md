# Sluice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sluice, a 10 HP quad VCA in the Instrument look: four DC-coupled polyphonic VCAs whose CV adds to Level, inputs normalled down a brass rope, outputs mixed downward, and one Lin/Exp switch.

**Architecture:** The per-sample logic is in a Rack-free `rka::SluiceEngine` (`src/sluice/SluiceEngine.hpp`). `Sluice.cpp` only fills a `SluiceFrame` from the ports, calls the engine and writes a `SluiceResult`, as `Fathom.cpp` does. The panel comes from a new `"Sluice"` entry in `tools/gen_panels.py`, which gains one primitive, the rope. The bench, the libm check and the globals check pick the engine up from `src/sluice/bench.inc`.

**Tech Stack:** C++11 plugin code (Rack SDK 2.6.6), C++17 offline tests with `src/testing.hpp`, the Python 3 panel generator, and Inkscape 1.4.4 for `make panels`.

**Spec:** `docs/specs/2026-11-15-sluice-design.md` (approved). Testing rules: `TESTING.md`. The look: `docs/DESIGN-THEME.md`. Read the spec before any task. Where this plan and the spec disagree, the spec wins; report the difference.

## Global Constraints

- Build with `RACK_DIR=$HOME/ws/sdk/Rack-SDK-2.6.6-mac-arm64` on the Mac. Start Rack only through `make smoke`.
- Voltages: audio ±5 V, bipolar CV ±5 V, unipolar 0–10 V. No clipping or saturation anywhere in Sluice.
- `p = clamp(Level + CV / 10 V, 0, 1)` per voice. Gain is `curve(p)` and never exceeds 1.
- Lin: `curve(p) = p`. Exp: `curve(p) = 10^(60·(p−1)/20) · min(1, p / 0.05)`, through `rka::fastDbToGain`.
- Level runs 0–1, shown as 0–100 %, and defaults to **0** (closed). CURVE defaults to **1 = Exp**.
- Level is smoothed with a one-pole of 10 ms. The smoother starts at the saved value and settles exactly on its target. CV is never smoothed. A CURVE change applies at once.
- An unpatched CV is 0 V; CV does not follow the rope.
- The rope: an unpatched input takes the row above's *input* (signal and channel count). Row A unpatched is silence.
- The mix downward: an unpatched output adds its signal into the next row's output, and a patched output stops the carry.
  - A mono row spreads into every voice of a wider row.
  - Polyphonic rows mix voice by voice.
  - The mixed signal has as many voices as its widest row.
  - Nothing scales the sum, so copies add up (4× is intended).
- Polyphony: a row has as many voices as its input after the rope, up to 16. A mono CV drives every voice, a polyphonic CV drives voice by voice (`getPolyVoltage`), and a row with no signal outputs 1 channel at 0 V.
- The light shows the highest `p` among the row's voices, using the smoothed Level and before the curve.
- NaN and ±inf on any input, CV or param become 0 where they enter the engine.
- Bypass: `configBypass(IN_x, OUT_x)` per row.
- No libm call on the per-sample path. Use `src/FastMath.hpp`, and use comparisons for clamps, as `FathomEngine::clampF` does.
- No allocation in `process()`. No writable globals in the engine.
- Plugin code is C++11. Never hand-edit `res/`, `res-src/` or `src/sluice/SluiceLayout.hpp`; run `make panels`.
- Slug `Sluice`, folder `sluice`. Ids are pinned from the first build and never reordered (Task 4 lists them).
- Before a task is done: `make test`. From Task 4 on, also run `make` and `make smoke`, and look at `build/screenshots/Sluice.png`.

## Review Focus

1. **A rope chain broken in the middle.** If A and C are patched and B is not, B takes A's input and D takes C's. Test: `rope_restarts_at_patched_input` (Task 2).
2. **Patched outputs at the top and bottom only.** If A and D are patched and B and C are not, A carries only itself, and D carries B + C + D. Test: all 16 output patterns, in `mix_all_patterns` (Task 2).
3. **A polyphonic CV on a mono input.** The row stays mono, and only CV channel 0 drives it. Test: `poly_cv_mono_input_stays_mono` (Task 2).
4. **A NaN arriving on row A's input with only D patched.** D must stay finite, and so must every other output. Test: `nan_does_not_travel` (Task 3).
5. **A sample-rate change mid-glide.** The smoother keeps a 10 ms time constant at the new rate. Test: `smoothing_time_follows_sample_rate` (Task 3).

### Task 2: The engine

**Files:**
- Create: `src/sluice/SluiceEngine.hpp`
- Create: `src/sluice/test_engine.cpp`
- Modify: `tests.mk`: add `build/test/sluice/test_engine` to `PLUGIN_MATH_TESTS`.
- Modify: `Makefile`: `MODULES = sway fathom shoal sluice`.

**Interfaces:**
- Produces (namespace `rka`):
  - `struct SluicePort { const float* v = nullptr; int channels = 0; float poly(int c) const; };`. `poly` behaves like `SwayPort::poly`: a mono cable drives every channel, and channels beyond the count read 0. Define it here; do not include Sway's header.
  - `struct SluiceFrame`:
    - `static const int ROWS = 4, MAX_CHANNELS = 16;`
    - `enum Param { LEVEL_A, LEVEL_B, LEVEL_C, LEVEL_D, CURVE, PARAMS_LEN };`, where `CURVE` is 0 for Lin and 1 for Exp;
    - `float params[PARAMS_LEN] = {};`
    - `SluicePort in[ROWS];` and `SluicePort cv[ROWS];`
    - `bool outConnected[ROWS] = {};`
  - `struct SluiceResult { float out[4][16]; int channels[4]; float light[4]; };`
  - `inline float sluiceCurve(float p, bool exp);`, which expects `p` in [0, 1].
  - `struct SluiceEngine { void reset(); void process(const SluiceFrame& f, float sampleRate, SluiceResult& r); };`. `reset()` is the module's Initialize; the next `process` snaps the smoothers to their targets.

- [ ] **Step 1: Write the failing tests** in `src/sluice/test_engine.cpp`. Copy the style of `src/fathom/test_engine.cpp`, with `CHECK` and `rkatest::finish("sluice test_engine")`.
  - A helper fills a frame from plain arrays, for example `Patch` with voltages, channel counts and connected flags per row. Run a few samples at 48 kHz so the smoothing settles, except where a test needs the first sample.
  - Every expected value is computed independently in the test: `in × p` for Lin, and `in × std::pow(10.f, 3.f*(p-1)) × std::min(1.f, p/0.05f)` for Exp. Use libm in the test, never `sluiceCurve`.

  The tests:
  - `curve_endpoints`: `sluiceCurve(0, e) == 0` and `sluiceCurve(1, e) == 1` for both `e`. `sluiceCurve(0.5f, false) == 0.5f`.
  - `exp_curve_matches_db_taper`: over 100 001 points in [0.05, 1], within 2e-6 relative of the libm formula. Over [0, 0.05], within 2e-6 relative of it, ramp included.
  - `exp_curve_monotonic_and_continuous`: over 1 000 001 points in [0, 1], each value is ≥ the one before. The largest step between neighbours is < 1e-4.
  - `lin_exact_on_dc`: Lin, Level 0.5, a 3.0 V DC input, CV unpatched. The output is exactly 1.5f after settling.
  - `cv_adds_to_level`: Lin, Level 0.5. CV +5 V gives `in × 1`; CV −5 V gives 0; CV +2 V gives `in × 0.7` (within 1e-6). Level 0 with CV +10 V gives `in`.
  - `unpatched_cv_is_still`: a moving CV on rows A, C and D, none on B, Level B 0.5. B's output is constant.
  - `rope_carries_signal_and_channels`: only A patched, 3 channels, all Levels 1, Lin. B, C and D each output A's input, with `channels == 3`.
  - `rope_restarts_at_patched_input`: A and C patched with different DC levels. B gets A's input and D gets C's.
  - `row_a_unpatched_is_silence`: nothing patched, all Levels 1. Every output is 0 V with `channels == 1`.
  - `mix_all_patterns`: four distinct DC inputs (1, 2, 4 and 8 mV, so every sum is unique), all Levels 1, Lin. For each of the 16 `outConnected` patterns, each connected output carries exactly the rows the rule gives. Row D carries the carry even when unpatched; the test checks connected outputs only.
  - `rope_copies_add_up`: one input on A, only D connected, Levels 1. D is exactly 4 × the input.
  - `mono_row_spreads_into_poly`: B is mono 1 V, C is 2 channels (0.5, −0.5), only C connected, Levels 1. C is (1.5, 0.5) with `channels == 2`.
  - `poly_rows_mix_voice_by_voice`: B has 2 channels, C has 4, only C connected. The sum's voices 1–2 include B; voices 3–4 do not.
  - `mono_cv_drives_every_voice`, `poly_cv_maps_voice_by_voice` and `short_cv_gives_zero_beyond`: a 4-channel input with a 1-, 4- or 2-channel CV respectively, checked per voice.
  - `poly_cv_mono_input_stays_mono`: a mono input with a 4-channel CV. `channels == 1`, and the gain comes from CV channel 0.
  - `sixteen_voices`: every row has 16 channels, and every voice is correct.
  - `light_is_max_p`: Exp, Level 0.5, a 2-channel CV (0 V, +2 V). The light is 0.7, which is `p`, not the gain.
  - `level_smoothing`: Lin, DC 1 V, Level stepped 0 → 1 after settling. The first sample after the step is < 0.01. The output is within 1 % of 1 V by 50 ms (5 τ). It equals 1.0f exactly within 200 ms.
  - `cv_not_smoothed`: a CV step from −5 V to +5 V with Level 0.5 changes the output on the same sample.
  - `starts_at_saved_level`: a fresh engine with Level 0.8 outputs `in × 0.8` on its very first sample. So does an engine after `reset()`.
  - `curve_switch_immediate`: Level 0.5. Flipping CURVE changes the gain from 0.5 to the Exp value on the next sample.

- [ ] **Step 2: Run them and see them fail.** Run `make test`. Expected: `test_engine.cpp` does not compile, because `SluiceEngine.hpp` is missing.

- [ ] **Step 3: Implement `SluiceEngine.hpp`.**
  - **Curve:** `sluiceCurve` uses `fastDbToGain(60.f * (p - 1.f))` for Exp.
  - **Per-row state:** a smoothed Level, plus a cache of the last `p` and gain per voice, so the curve is recomputed only when `p` changes.
  - **Smoother coefficient:** `1 - fastExp2(-1 / (0.010 * sampleRate * ln2))`, recomputed only when `sampleRate` changes. Snap to the target when within 1e-6.
  - **Each sample:**
    1. Resolve the rope for inputs.
    2. Compute each row's voices.
    3. Walk the mix from A to D with a carry buffer, so that `out[r]` is row r's own signal plus the carry. A connected output clears the carry.
  - **Unpatched outputs:** `out[r]` holds the same sum as a connected one would.

- [ ] **Step 4: Run them and see them pass.** Run `make test`. Expected: `sluice test_engine: all checks passed`, and every other test still passes.

- [ ] **Step 5: Show a test fails when it should.** Temporarily break each of these and confirm the matching test fails, then restore it:
  - the carry clear;
  - the mono spread;
  - the `/0.05` ramp;
  - the smoother's start-up snap.
