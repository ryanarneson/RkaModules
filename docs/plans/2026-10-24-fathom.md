# Fathom (phase 1, the voice) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Fathom, a 10 HP bass drone voice (sub sine + 7-saw supersaw + drift + low-pass), as the second `rka` module, with its DSP unit-tested offline and its "Orbit" panel generated.

**Architecture:** Four Rack-free headers in `src/fathom/` (`Svf`, `SuperSaw`, `Drift`, `DroneVoice` + `OutputStage`), each with a `test_*.cpp`; `src/fathom/Fathom.cpp` only maps params, CV and the menu onto them. Saws reuse `src/sway/Waves.hpp`'s polyBLEP. The panel comes from `tools/gen_panels.py`, which gains rings, lines, glyphs and below-the-knob labels.

**Tech Stack:** C++11 for the plugin (Rack SDK 2.6.6 `plugin.mk`), C++17 for offline tests, Python 3 + Inkscape for panels, VCV Rack 2 for `make smoke`.

**Spec:** `docs/specs/2026-10-24-fathom-design.md` (read it first; this plan does not repeat its tables).

## Global Constraints

- Plugin slug `rka`, module slug `Fathom`, folder `src/fathom/`; version stays `2.0.0` (unreleased).
- Plugin code compiles as C++11 (`plugin.mk`); `test_*.cpp` may use C++17. CI compiles tests with `-Wall -Wextra -Werror`.
- DSP headers in `src/fathom/*.hpp` (except `FathomLayout.hpp`) must not include `rack.hpp`. Sway's headers are included as `"sway/Waves.hpp"` etc. (`-Isrc` is on every compile line).
- Do not define anything named `rka::Voice`, `rka::VoiceBank` or `rka::VoiceInput`: Sway owns those names and both modules link into one plugin.
- Never hand-edit `res/`, `res-src/`, `src/*/*Layout.hpp`, `src/RkaTheme.hpp`; run `make panels`.
- Voltages: audio out ±5 V; V/OCT 1 V/oct; CV ±5 V at full attenuverter sweeps a knob's range; CUTOFF CV is 1 V/oct at full. Inputs read channel 0.
- Use `rka::` widgets from `src/widgets.hpp` and `ThemedPJ301MPort` / `ThemedScrew`, never stock knobs.
- Tools stay portable (macOS + Linux): no `sed -i`, no GNU-only flags.
- Every shell needs `RACK_DIR=$HOME/ws/sdk/Rack-SDK-2.6.6-mac-arm64` (non-interactive shells don't read `~/.zshrc`).
- Done per task: `make test` passes; for tasks touching the plugin also `make` with no warnings and `make smoke` prints `ok: Sway` and `ok: Fathom`.
- Oneiroi's detune and volume tables are GPL-3-or-later; the header that carries them credits Befaco/Oneiroi and Szabo.

## Review Focus

1. V/OCT far below range (e.g. −10 V) → `f0` clamps at 8 Hz, the sub keeps running at 4 Hz, every output is finite (test in Task 4).
2. Sample rate change (48 kHz → 96 kHz) → the same note has the same period in seconds, and the filters do not blow up (tests in Task 1 and Task 4).
3. CUTOFF CV pushing the cutoff past Nyquist at 44.1 kHz → clamped to 0.45·fs, output bounded (test in Task 1).
4. DETUNE or DRIFT CV driving the value outside 0…1 → clamped, tables never indexed with a negative detune (tests in Task 2 and Task 3).
5. DRIFT turned from 100 % to 0 mid-walk → offsets slew back to zero over about a second, no step (test in Task 3).

- `static const float BUTTERWORTH_K = 1.41421356f;`
- `struct Svf { void reset(); void setCoefficients(float cutoffHz, float k, float sampleRate); struct Out { float lp, bp, hp; }; Out process(float in); }`
  - `setCoefficients`: `fc = min(cutoffHz, 0.45f * sampleRate)`, `fc = max(fc, 1.f)`; `g = tan(π · fc / sampleRate)`; `a1 = 1 / (1 + g (g + k))`, `a2 = g · a1`, `a3 = g · a2`; stores `k`.

  - A default-constructed `Svf` has `k = BUTTERWORTH_K` and coefficients for 1 kHz at 48 kHz (so `process` before `setCoefficients` is harmless).

### Task 2: SuperSaw

**Files:**
- Create: `src/fathom/SuperSaw.hpp`, `src/fathom/test_supersaw.cpp`

**Interfaces (namespace `rka`, `SuperSaw.hpp`, C++11; includes `"sway/Waves.hpp"`):**
- `struct SuperSaw { static const int N = 7; double phase[N]; float ratio[N]; float volume[N]; float gain; void reset(); void setDetune(float detune); void process(float f0Hz, const float* pitchRatio, const float* levelGain, float spread, float dt, float& left, float& right); }`
  - `reset()`: all phases 0 (coherent start: at DETUNE 0 the seven saws are one saw).
  - `setDetune(d)`: `d = clamp(d, 0, 1)`; `detune = 0.4·d`; `ratio[0..6] = 1 − detune·0.11002313, 1 − detune·0.06288439, 1 − detune·0.01952356, 1, 1 + detune·0.01991221, 1 + detune·0.06216538, 1 + detune·0.10745242`; `v = clamp(0.5·d, 0.005, 0.5)`; `side = −0.73764·v² + 1.2841·v + 0.044372`; `volume[3] = −0.55366·v + 0.99785`, all other `volume[i] = side`; `gain = 0.3·(1.4 − detune)`. The file header credits Befaco Oneiroi `StereoSuperSaw.h` (GPL-3-or-later) and Szabo 2010.
  - `process`: for saw `i`, `dti = f0Hz · ratio[i] · pitchRatio[i] · dt`, advance `phase[i]` (wrap with `floor`), `s = sawBlep(float(phase[i]), dti) · volume[i] · levelGain[i] · gain`; pan `pos = spread · (i − 3) / 3`, `a = (pos + 1) · π/4`, `left += s·cos(a)`, `right += s·sin(a)`. `pitchRatio` / `levelGain` may be null meaning all 1.
  - Consequence to state in a comment: at `spread = 0` each side carries `√½ ·` the mono sum.

### Task 3: Drift

**Files:**
- Create: `src/fathom/Drift.hpp`, `src/fathom/test_drift.cpp`

**Interfaces (namespace `rka`, `Drift.hpp`, C++11):**
- `struct DriftWalk { explicit DriftWalk(uint64_t seed = 1); float cents; float db; void process(float amount, float dt); }`
  - Random source: splitmix64 as in `src/sway/RandomGen.hpp` (copy the `uniform()` step; do not include `RandomGen.hpp`, its API is cycle-based).
  - State: `targetCents`, `targetDb`, `timer` (seconds left until the next draw), slewed `cents`, `db`.
  - `process(amount, dt)`: `timer −= dt`; when `timer ≤ 0`: `targetCents = 6 · amount · u`, `targetDb = −3 · amount · (0.5 + 0.5·u')` with `u, u'` uniform in [−1, 1]; `timer = 0.5 · (1 + 0.25·u'')`. Then one-pole slew of `cents` and `db` toward their targets with `τ = 1 s`: coefficient `1 − exp(−dt/τ)`, cached and recomputed only when `dt` changes. `amount` is clamped to 0…1. Initial targets are 0 and the first draw happens on the first call (timer starts at 0).
- `struct Drift { static const int N = 7; DriftWalk saws[N]; DriftWalk sub; float pitchRatio[N]; float levelGain[N]; float subGain; Drift(); void process(float amount, float dt); }`
  - Constructor seeds `saws[i]` with `i + 1` and `sub` with `100`.
  - `process`: steps every walk, then `pitchRatio[i] = exp2(saws[i].cents / 1200)`, `levelGain[i] = pow(10, saws[i].db / 20)`, `subGain = pow(10, sub.db / 20)`. The sub's `cents` is ignored.

  - `testBounds`: `amount = 1`, 60 s: every `cents` in [−6, 6], every `db` in [−3, 0].
  - `testSlewed`: `amount = 1`, 60 s: every per-sample `|Δcents| < 1e-3` and `|Δdb| < 5e-4`.
  - `testWalksDiffer`: two `DriftWalk`s seeded 1 and 2, 10 s at `amount = 1`: their `cents` differ by more than 0.5 at some sample.

  - `testAmountClamps`: `amount = 3` behaves within the `amount = 1` bounds (Review Focus 4).

### Task 4: DroneVoice and OutputStage

**Files:**
- Create: `src/fathom/DroneVoice.hpp`, `src/fathom/test_voice.cpp`

**Interfaces (namespace `rka`, `DroneVoice.hpp`, C++11; includes `Svf.hpp`, `SuperSaw.hpp`, `Drift.hpp`, `"sway/Waves.hpp"`):**
- `static const float F0_MIN = 8.f; static const float F0_MAX = 4000.f; static const float PITCH_SLEW_SEC = 0.005f; static const float SUB_GAIN = 0.6f;`
- `struct DroneVoice { SuperSaw saws; Drift drift; Svf hpLeft, hpRight; double subPhase; float f0; int block; struct Out { float left, right, sub; }; void reset(float f0Hz); Out process(float f0Hz, float detune, float spread, float driftAmount, float subLevel, int subOctaves, float sampleRate); }`
  - `reset(f0Hz)`: phases 0, `f0 = clamp(f0Hz, F0_MIN, F0_MAX)`, HP coefficients set for `f0`, `block = 0`.
  - `process`: `dt = 1/sampleRate`; target `= clamp(f0Hz, F0_MIN, F0_MAX)`; `f0 += (target − f0) · (1 − exp(−dt / PITCH_SLEW_SEC))` (coefficient cached per sample rate); every 16 samples (`block` counter) `hpLeft/hpRight.setCoefficients(f0, BUTTERWORTH_K, sampleRate)`; `saws.setDetune(detune)`; `drift.process(driftAmount, dt)`; `saws.process(f0, drift.pitchRatio, drift.levelGain, clamp(spread, 0, 1), dt, l, r)`; `l = hpLeft.process(l).hp`, same for `r`; sub: `subPhase += f0 / (subOctaves == 2 ? 4 : 2) · dt`, wrap, `sub = waveSin(float(subPhase))`; `left = l + clamp(subLevel, 0, 1) · SUB_GAIN · drift.subGain · sub`, `right` likewise; `Out{left, right, sub}` (`sub` is the raw ±1 sine).
- `struct DcBlock { float x1, y1; float process(float x, float coef); }` with `y = x − x1 + coef · y1`; `coef = exp(−2π · 2 Hz / sampleRate)` computed by the caller.
- `struct OutputStage { Svf lpLeft, lpRight; DcBlock dcLeft, dcRight; int block; void process(float cutoffHz, float sampleRate, float& left, float& right); }`
  - Every 16 samples set both LP coefficients to `cutoffHz` with `BUTTERWORTH_K`; `left = dcLeft.process(tanh(lpLeft.process(left).lp), coef)`, same for right. Output is nominal ±1; the module scales by 5 V.
