# Pan (and Ballast #38, #39, #40) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- **Phase 1:** Ballast's fixes and contract changes:
  - the source type;
  - normals both ways;
  - one expander of each kind;
  - `linked()`;
  - #38, #39 and the rest of #40.
- **Phase 2:** Pan, a 6 HP Ballast expander with a pan knob, attenuverter and CV per channel, and two stereo modes.

**Architecture:**
- **Ballast:** the contract lives in `src/ballast/BallastExpander.hpp`, the walk in `BallastChain.hpp`, and the engine in `BallastEngine.hpp`.
- **Pan's core:** `rka::PanCore` (`src/pan/PanCore.hpp`), a Rack-free `BallastExpander`.
  - On `linked()` it reads its controls through a virtual `readFrame` and advances the smoothing.
  - On `postLevel` it applies the pan laws.
- **Pan's module:** `Pan.cpp` subclasses Module and PanCore. It implements `readFrame` from its params and inputs, and drives LINK.

**Tech Stack:** C++11 plugin code (Rack SDK 2.6.6), C++17 offline tests with `src/testing.hpp`, the Python 3 panel generator, and Inkscape 1.4.4.

**Spec:** `docs/specs/2026-11-17-pan-design.md`, with its mockup `docs/specs/2026-11-17-pan-mockup.png`. Background: `docs/specs/2026-11-17-ballast-design.md` and `TESTING.md`. Read the spec before any task. Where this plan and the spec disagree, the spec wins; report the difference.

## Global Constraints

- **Build:** with `RACK_DIR=$HOME/ws/sdk/Rack-SDK-2.6.6-mac-arm64`. Agents start Rack only through `make smoke`.
  - Before every `make install`, `mac_dist` or `cross_build`, run `tools/bump_version.sh "<what changed>"`.
- **Test results:** test results beyond unit tests, and any audio, go on `/Volumes/share1/VCVRACK/`, never in the repo.
- **Contract:**
  - `enum BallastSource { STEREO, MONO }`. MONO means exactly one of IN L and IN R is patched; l and r then both hold that jack's signal.
  - `postLevel(int ch, float& l, float& r, BallastSource src)`.
  - `virtual int kind() const` (default 0) and `virtual void linked()` (default nothing).
  - Pan's kind is 1.
- **The walk:**
  - Bypassed expanders are skipped, and don't claim their kind.
  - Only the first unbypassed expander of each nonzero kind is kept. Later ones are not called, but don't end the chain.
  - A module that is not a `BallastExpander` ends the chain.
  - `linked()` is called on every kept expander on every sample the walk runs, whether or not an output is patched. The walk runs whenever `onExpanderChange` says the right-hand neighbour is an expander.
- **Normals:** either input alone is a centred mono source (IN R normalled to IN L, and IN L to IN R). This is a released behaviour change (2.0.7 played IN R alone right-only), so CHANGELOG and manual say so.
- **#38:** while the DC blocker is off its state tracks the input as the output (x1 = y1 = input), so turning it on starts at the input's level and an offset fades away with no step.
- **#39:** `setSampleRate` recomputes coefficients only. The DC blocker state and the knob smoothing carry on; construction and `reset()` start clean.
- **#40:**
  - `dcBlock` loads as on unless the saved value is JSON `false`.
  - The CLIP hold is at least 1 sample.
  - The manual says "almost no work" with neither output patched.
  - The mono switch is tested both ways, and the expander tests are run with the blocker on as well.
- **Pan knob and CV:**
  - The param runs 0..1 with 0.5 as centre, the default.
  - position = clamp(knob + CV/10 × att, 0, 1), and p = 2·position − 1.
  - The attenuverter runs −1..1, default 0. A poly CV uses channel 1.
  - The knob is smoothed (one-pole, about 10 ms, snapping on first link); CV is not.
- **Pan laws:** p = 0 is exactly the identity, bit for bit, in every law.
  - **Mono:** gL = √2·cos θ, gR = √2·sin θ, θ = (p+1)·π/4.
  - **Stereo true pan** (default): for p ≥ 0, θ = p·π/2, L' = L·cos θ and R' = R + L·sin θ; mirrored for p < 0.
  - **Stereo balance:** for p ≥ 0, L' = L·cos(p·π/2) and R' = R; mirrored.
  - Use FastMath (`fastSin2pi`), no libm per sample.
- **Attach and detach:**
  - On the first `linked()` after not being linked for more than 2 of Pan's process calls, the smoothing restarts from centre (p = 0) and glides to the knob.
  - Detach or bypass is a step back to centre, documented in the manual.
- **LINK:** lit while Pan was linked within the last 50 ms. The flag is shared across threads through `std::atomic<int>` (Pan.cpp only).
- **Pan menu:** "Stereo sources: True pan / Balance", saved as `stereoMode` (0 true pan, 1 balance; a missing or invalid value is 0).
- **Ballast menu:** "Add Pan expander", placed against Ballast's right side by pushing neighbours (Venom's `addExpander`, `~/ws/plugins/VenomModules/src/Venom.hpp:575`). Greyed while an unbypassed Pan is in the chain.
- **Engine rules:**
  - no libm per sample, no allocation in hooks or `process()`, no writable globals;
  - NaN and inf read 0, NaN-safe;
  - plugin code is C++11.
- **The libm check:** before each engine task closes, run the Linux check:
  `/private/tmp/claude-501/-Users-rarneson-ws/97691046-d5f6-488f-b6d4-8130759f4663/scratchpad/linux_libm.sh libm-calls`. It copies tracked and new files and runs `make -f tests.mk libm-calls CXX=g++` in the toolchain image. Read the output, not the exit code.
- **Generated files:** never hand-edit `res/`, `res-src/` or `src/pan/PanLayout.hpp`. Run `make panels`.
- **Pan ids:** slug `Pan`, folder `pan`.
  - params `PAN_1 … PAN_4` (0–3), then `PAN_1_ATT … PAN_4_ATT` (4–7);
  - inputs `PAN_1_CV … PAN_4_CV` (0–3);
  - no outputs;
  - lights `LINK` (0).
- **Before a task is done:** `make test`. When a task touches the module or panels, also `make` and `make smoke`, and look at `build/screenshots/*.png`.

## Review Focus

1. **A Pan attached at centre, every source kind** (mono via IN L, mono via IN R, stereo, unpatched): the output is bit-identical to Ballast alone (`centre_is_identity`, Task 4).
2. **Two Pans, the first bypassed.** The second acts, and only one Pan ever acts (`one_of_each_kind`, Task 1).
3. **Turning the DC blocker on with 2 V DC present.** No output step beyond the steady-state step (`dc_on_no_step`, Task 2).
4. **A sample-rate change mid-run with DC present and a knob gliding.** No step in the output (`rate_change_keeps_state`, Task 2).
5. **Pan CV at audio rate,** a 1 kHz ±5 V sine at full attenuverter on a mono source: L² + R² stays constant within 0.1 dB on every sample (`mono_equal_power_under_cv`, Task 4).

### Task 4: PanCore: the laws, the CV law, smoothing, attach

**Files:**
- Create: `src/pan/PanCore.hpp` and `src/pan/test_core.cpp`.
- Modify: `tests.mk` (`build/test/pan/test_core` in `PLUGIN_MATH_TESTS`) and `Makefile` (`MODULES += pan`).

**Interfaces (namespace `rka`):**
- `struct PanFrame { float knob[4], att[4]; BallastPort cv[4]; int stereoMode; }`, where `stereoMode` is 0 for true pan and 1 for balance.
- `class PanCore : public BallastExpander`:
  - `static const int KIND = 1;`, with `int kind() const override` returning `KIND`;
  - `void setSampleRate(float fs)`, which ignores unusable rates;
  - `void linked() override`:
    - calls `readFrame(frame_)`;
    - if `idle()` is above 2, restarts the smoothing from centre;
    - advances the smoothing one sample;
    - computes each channel's target p;
  - `void postLevel(int ch, float& l, float& r, BallastSource src) override`, which applies the law for channel ch;
  - `protected: virtual void readFrame(PanFrame& f) = 0;`
  - `protected: virtual int idle() const { return 0; }`, which Pan.cpp overrides with its atomic counter;
  - test hook `float position(int ch) const`, the smoothed position.

- [ ] **Step 1: Write the failing tests**, with a `struct TestPan : PanCore` whose `readFrame` copies a test `PanFrame` and whose `idle` returns a settable value. Run it through `BallastEngine` where noted:
  - `centre_is_identity`: through a `BallastEngine` with the TestPan in the chain, both stereo modes, and channels fed mono via IN L, mono via IN R, stereo, and unpatched. Noise for 2 s matches a Ballast without Pan bit for bit.
  - `mono_law`: at p = −1, L = √2·x and R = 0; at p = +1 the mirror. At every p in steps of 0.05, L² + R² = 2x² within 0.05 dB.
  - `mono_equal_power_under_cv`: from the Review Focus.
  - `true_pan`: at p = +1, L' = 0 and R' = R + L; at p = 0.5, L' = L·cos(π/4) and R' = R + L·sin(π/4) within 1e-5; mirrored for p < 0.
  - `balance`: at p = +1, L' = 0 and R' = R; at p = −0.5, R' = R·cos(π/4) and L' = L.
  - `cv_law`: knob 0.5, att 1, CV +5 V gives p = +1; att −1, CV +5 V gives p = −1; att 0 ignores the CV; knob 1 with CV +5 V clamps to +1.
  - `knob_smoothing`: a knob step from 0.5 to 1 moves `position` by at most 5 % of the step per sample and settles within 50 ms. CV is not smoothed: a CV step reaches the output on the same sample.
  - `attach_glides_from_centre`: with idle > 2, the first `linked()` starts at position 0.5 even with the knob at 1, then glides.
  - `poly_cv_uses_channel_1`.
- [ ] **Step 2: Run them and see them fail** (`make build/test/pan/test_core && ./build/test/pan/test_core`).
- [ ] **Step 3: Implement.**

  - p == 0 exactly returns without touching l and r.
- [ ] **Step 4: Run them and see them pass.** Show each can fail by mutation, one at a time:
