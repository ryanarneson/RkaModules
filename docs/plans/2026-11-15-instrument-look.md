# Instrument Look Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sway, Fathom and Shoal are rebuilt in the "Instrument" look (brass and ivory on near-black, enamel dial faces, knurled knobs, traced CV paths), and Nightglow is removed.

**Architecture:** `tools/gen_panels.py` gains the Instrument language beside Nightglow: a palette, drawing primitives (arcs, graduated limbs, enamel faces, output tiles, traces, screen bezels), geometry helpers, and generated component artwork for the plugin's own knobs, port, switch and lights. Each module's panel description is rewritten in that language in its own task, with new widget classes added beside the old ones so an unconverted module never changes. When all three have moved, the Nightglow code, components and colours are deleted. No DSP, parameter, range or patch-format change, except one added light on Sway.

**Tech Stack:** Python 3 panel generator, Inkscape for text-to-path (`make panels`), C++11 plugin code (Rack SDK 2.6.6), nanosvg as Rack's SVG renderer.

**Spec:** `docs/specs/2026-11-15-instrument-look-design.md` (with its three mockups, which are sketches, not drawings to trace; where a mockup and the text disagree, the text wins). Summary: `docs/DESIGN-THEME.md`. Testing rules: `TESTING.md`.

## Global Constraints

- Palette (spec's working values): ground `#15171c`, construction `#2c3340`, brass `#c9a46a`, ivory `#efe6d2`, ink `#1c1a16`, dim `#8a8474`, knob body `#23262d`, glass `#05080c`, signal `#6fd6e0`. Cyan is used only for lights and screen contents.
- **Nothing is decoration.** Every drawn line is a scale, a centre mark, a construction line, a signal trace or a label.
- No frames round groups of jacks or controls. No monospace lettering on a panel (screen contents may be monospace). No glow, no gradient on the ground.
- Every CV input has one unbroken trace from jack through attenuverter to the control it moves, meeting the control aimed at its centre; a trace never grazes a control's edge and traces do not cross. Traces are drawn under the controls.
- Outputs sit on ivory tiles with the name in ink; inputs are bare.
- A dial turns clockwise for more.
- The mark "R K A · INSTRUMENTS" is one small dim line centred at the foot of the panel and overlaps no knob, button, jack or tile; the generator fails if it would.
- Parameter, input, output and existing light ids never change number. No DSP, range or patch-format change. Saved patches load.
- Panels, `src/<module>/*Layout.hpp`, `src/RkaTheme.hpp` and `res/components/*` are generated by `tools/gen_panels.py`; never hand-edited. Until the last task, regenerating leaves every not-yet-converted module's outputs byte-identical.
- New widgets, component SVGs and colours are added beside the Nightglow ones and used only by converted modules. Nightglow is deleted only in the last task.
- nanosvg draws flat fills, strokes, linear and radial gradients and opacity: no blur, no filters, no text, and dashed strokes are not relied on. Knurling is drawn as individual ticks.
- A knob's artwork is split into a static part and a rotating part where anything on it must not turn (scale, bezel), as `rka::Trim` is today.
- Rack's dark-panels preference gets the same drawing turned down (deeper ground, dimmer ivory and brass), not a different design.
- Plugin code is C++11. Scripts stay portable across macOS and Linux; `make panels` must produce the same output on either given the same typeface.
- `TESTING.md` applies: generator logic that can be wrong (geometry, clearance) gets offline tests that are shown to fail; every panel change is looked at in `build/screenshots/`; the Linux and Windows builds run on the final commit.
- Before calling a task done: `make test`, `make`, `make smoke`, and view the changed module's screenshot beside its mockup. Build with `RACK_DIR=$HOME/ws/sdk/Rack-SDK-2.6.6-mac-arm64`. Start Rack only through `make smoke`.
- Commit per task on the working branch; never push. Commit messages end with a `Co-Authored-By:` trailer naming the model that wrote the commit.

## Decisions taken in this plan

The spec leaves these open; each is the planner's call and is listed for the owner's review.

1. **All three modules on one branch, one pull request.** The owner asked for the three to be rebuilt together, so nothing ships in a mixed state. The version stays 2.0.0 (unreleased); the changelog entries are edited in place.
2. **Shoal is built now**, against its layout as it stands after friendly mode, using the spec's Shoal section as the direction. Positions follow the mockup where the current feature set allows.
3. **Typeface (decided by the owner, 2026-11-15): D-DIN Condensed for everything,** one face only, in its two weights (Regular and Bold). It is Datto's open DIN 1451 digitisation (SIL OFL 1.1, from github.com/amcchord/datto-d-din). `D-DINCondensed.ttf`, `D-DINCondensed-Bold.ttf`, the licence (`COPYING.txt`, `OFL-1.1.txt`) and a short README naming the source go in `tools/fonts/`, so `make panels` gives the same result on any machine. The generator points Inkscape at that folder (a private fontconfig file) and never falls back to a system font: if the face is missing, `make panels` fails. Where a label does not fit, it is shortened or the layout is changed; no second face. Chosen over Barlow Condensed, DejaVu Sans Condensed and D-DIN (normal width) from a side-by-side render of the Sway mockup; the mockups' DIN Alternate is a commercial font and cannot be used.
4. **Sway's rate light** follows channel 1: lit for the first half of each cycle, and steady at half brightness above 10 Hz where blinking stops being readable. One new light id, appended last.
5. **Shoal's lights follow "cyan means lit":** trigger lights become cyan; each output light is cyan with brightness from the voltage's magnitude (|V| / 5), replacing the cyan/magenta pair. The busy banner in the list moves from amber to brass and ivory.
6. **Shoal's screens keep their size** (0.65 mm per firmware pixel) and move 4 mm lower as in the mockup, if the generator's clearance checks allow.

## Review Focus

1. **Legibility at rack zoom.** Dim lettering on a near-black ground, ink on ivory, and 1.5–2 mm labels must be readable at 100 % zoom in both normal and dark-panel variants. Each module task views both screenshots at 100 %.
2. **A trace that grazes or crosses.** Tasks 1–3: the generator checks every trace against every control it does not belong to, and that no two traces cross; a test feeds it a layout that violates each.
3. **Sway at 12 HP in an existing patch.** Ids unchanged, so a saved patch loads; neighbours to the right gain a 6 HP gap. Task 2 checks ids against `main`; a manual check covers a real patch.
4. **Knob artwork that rotates when it should not** (a scale or bezel turning with the knob), or a pointer that does not reach its scale. Task 1's specimen and each module's screenshot at two knob positions.
5. **Something still Nightglow after the last task**: a colour constant, a component SVG, a stock knob, a doc sentence. Task 5 greps for each.

**Interfaces:**
- Consumes: the generator as it stands (`PANELS`, `THEMES`, `RADII`, `check_clearance`, `check_screens`, `layout_hpp`, `theme_hpp`, `trim_svgs`).
- Produces:
  - A per-module `look` key in a panel description: `"nightglow"` (default, unchanged output) or `"instrument"`.
  - Instrument primitives usable from a description: origin crosshair; construction circle and radius; limb (brass arc graduated on its outer side, tick spacing and major interval given); enamel face (ivory disc, brass bezel, ink scale with tick count, major interval and optional numerals over a sweep); output tile (with name, optional light seat); trace (a list of points with at most one elbow, ending aimed at a control's centre and stopping at its edge); nameplate (module name large and ivory at top left, one-line description in dim); the foot mark; screen window (glass in a brass bezel, optional pixel rulers and numerals); labels in ivory, dim or ink.

  - Checks, each failing the build with a message naming the parts: component clearance (as today); a trace passing within clearance of a control it does not belong to; two traces crossing; the foot mark overlapping any component or tile; a label overlapping a component.
  - Component artwork generated to `res/components/`, in normal and dark variants, with a static and a rotating layer where needed: hero knob, face knob (mid), limb knob, attenuverter, encoder (no index), brass port, two-position switch (two frames), button cap (unlit and lit), light seat.
  - In `src/widgets.hpp`, beside the existing classes: `rka::HeroKnob`, `rka::FaceKnob`, `rka::LimbKnob`, `rka::Atten`, `rka::BrassPort`, `rka::Toggle2`, `rka::CapLatch` (a latching button whose cap lights cyan; with a light id for Sway's 1-SHOT, and param-only for Shoal's UI MODE), `rka::CapButton` (momentary, shift-click latch, as `HoldButton`), `rka::JewelLight` (cyan). Radii for clearance are recorded in the generator beside the existing `RADII`.
  - In `src/RkaTheme.hpp`, a second block of colours for code-drawn widgets: `GROUND`, `BRASS`, `IVORY`, `INK_ON_IVORY`, `DIM`, `KNOB`, `GLASS`, `SIGNAL`, with dark-panel values. Existing constants unchanged.

- Limb at radius 58, ticked every degree, longer every fifth, running off the left edge. PW, PHASE, SKEW, SMOOTH, MORPH on it in columns 1–5 (x = 6.98 + 9.4·i), each y from the column–arc helper; names above.
- All six attenuverters in the same columns on the radius-68 arc; all six CV jacks in a row at y = 88.
- Traces: columns 1–5 straight from jack through attenuverter to knob. FM: up column 0 from the jack through its attenuverter to y = 56, one elbow, aimed at the Rate dial's centre, stopping at its bezel; "FM" just right of the trace above the attenuverter.
- Rate at (21, 34) on an enamel face of radius about 16, numbered 0–10 over 270°, "RATE" in ink at the foot of the face, the rate light above the word.
- Spread at (46.5, 23) and Channels at (52, 40.5) on smaller faces, unnumbered, names beneath in dim.
- Row at y = 102: CLOCK, RESET, HOLD in columns 0–2; SIN, TRI, SAW on tiles in columns 3–5.
- Row at y = 116: BI/UNI (`Toggle2`) and 1-SHOT (`CapLatch`, cap lights cyan) in columns 0–1; SQR, MORPH, RAND, EOC on tiles in columns 2–5. The foot mark must clear this row.
