# Wake Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wake, a 14 HP stereo echo in the Instrument look: 10 ms to 10 s, three styles (Tape, Analog, Digital), Ratio between the sides, Ping Pong, Freeze, Diffuse, Drift, a clock input, and CV on Time, Feedback and Mix.

**Architecture:**
- **Shared:** `src/DelayTap.hpp`, a moving read point over a `rka::DelayLine`: glide (pitch bends), crossfade (no bend) and a frozen loop. Eddy and Spindrift will reuse it.
- **Engine:** a Rack-free `rka::WakeEngine` (`src/wake/WakeEngine.hpp`) built from small headers: the time laws and clock follower, the loop colour, the smear, two delay sides.
- **Module:** `Wake.cpp` only maps ports, params, the Style button and patch state onto the engine.
- **Panel:** the draft `"Wake"` entry, kept as a patch at `docs/plans/2026-11-20-wake-panel-draft.patch` (apply with `git apply`; delete it in Task 1), approved by the user with the button lettered PING PONG.

**Tech Stack:** C++11 plugin code (Rack SDK 2.6.6), C++17 offline tests with `src/testing.hpp`, the Python 3 panel generator, Inkscape.

**Spec:** `docs/specs/2026-11-20-wake-design.md`, mockup `docs/specs/2026-11-20-wake-mockup.png`. Testing rules: `TESTING.md`. Code to read first: `src/DelayLine.hpp`, `src/rigging/RiggingEngine.hpp` and `String.hpp` (frame, control rate, ramps, bound), `src/hadal/Drift.hpp` (`Wander`), `src/fog/Diffuser.hpp`. Read the spec before any task. Where this plan and the spec disagree, the spec wins; ledger the difference.

## Global Constraints

- **Build:** `RACK_DIR=$HOME/ws/sdk/Rack-SDK-2.6.6-mac-arm64`. Agents start Rack only through `make smoke`. Before every `make install`, `mac_dist` or `cross_build`: `tools/bump_version.sh "<what changed>"`, and clear older `rka-*` packages from Rack's plugins folder (#45).
- **Repo:** unit tests only; no audio, no test results beyond unit tests (they go on `/Volumes/share1/VCVRACK/`).
- **Every test is shown to fail** (a mutation, named in the ledger; `sleep 1` before the rebuild). No libm per sample (`src/FastMath.hpp`); NaN-safe; no allocation in `process`.
- **Ids** (panel, layout header, module, in this order): params `TIME`, `TIME_ATT`, `FEEDBACK`, `TONE`, `RATIO`, `MIX`, `DIFFUSE`, `DRIFT`, `STYLE`, `FREEZE`, `PINGPONG`; inputs `FEEDBACK_CV`, `CLOCK`, `TIME_CV`, `FREEZE`, `MIX_CV`, `L`, `R`; outputs `L`, `R`; lights `TAPE`, `ANALOG`, `DIGITAL`, `FREEZE`, `PINGPONG`. Slug `Wake`.
- **Time:** knob k in 0..1, T = 0.01 s × 1000^k; default 300 ms (k = 0.4924). CV: T × 2^(volts × attenuverter), attenuverter −1..1, default 0. Held to 10 ms .. Tmax, where Tmax = min(10 s, what the buffer holds at this rate). This is the left side's time when Ratio is at or right of noon.
- **Clock:** rising edge 0.1 V / 1 V; period = samples between the last two edges. With CLOCK patched and two edges seen: step = round(9 × clamp(k + volts × attenuverter / 10, 0, 1)) into {1/4, 1/3, 1/2, 2/3, 3/4, 1, 3/2, 2, 3, 4}; T = period × multiple, halved while over Tmax, doubled while under 10 ms. A stopped clock holds its period.
- **Ratio:** knob 0..6 snapped, default 3. Factors f = {1/2, 2/3, 3/4}. 0, 1, 2: left = T × f[knob], right = T. 3: both T. 4, 5, 6: right = T × f[6 − knob], left = T. Neither side under 10 ms. Tooltip: "L 1:2", "L 2:3", "L 3:4", "1:1", "R 3:4", "R 2:3", "R 1:2".
- **Feedback:** gain = 1.1 × clamp(knob + volts / 10, 0, 1); default knob 0.3636 (40 %). The loop is bounded in every style.
- **Tone:** knob 0..1, noon flat. Left of noon: a low-pass from 20 kHz at noon down to 500 Hz, log. Right: a high-pass from 20 Hz up to 1 kHz, log. In the loop, before the output tap: the first echo passes it once.
- **Styles** (0 Tape, 1 Analog, 2 Digital; default 0; constants in `WakeTuning.hpp`): Tape and Analog glide on a Time change (pitch held within two octaves either way), saturate each pass and band-limit it (Tape about 40 Hz to 6 kHz; Analog 80 Hz to 5 kHz at 10 ms, falling log to 1.5 kHz at 1 s and beyond, with about twice Tape's drive). Digital crossfades (about 40 ms) and has no filter and no saturation below its bound. A style change ramps the constants over about 30 ms.
- **Diffuse:** 0..1, default 0. At 0 the smear is out of the path exactly. Above 0 the first echo's energy centroid moves by under 10 ms and its level by under 2 dB.
- **Drift:** 0..1, default 0.15. At 0 the times are constant to the sample. At 1 each side's pitch wanders within ±30 cents, independently.
- **Freeze:** frozen = the latch or GATE above 1 V (0.1 V / 1 V Schmitt). Writing stops; each side loops its last stretch, as long as its time at that moment, with a 10 ms crossfaded join (shorter for loops under 40 ms: a quarter of the loop). Time, Ratio, clock and Ping Pong are held until release. Drift still acts. Wet fades 10 ms in and out of freeze.
- **Ping Pong:** off: each side feeds itself. On: left write = (inL + inR) / 2 + Feedback × right loop output; right write = left loop output. Switching fades over about 10 ms.
- **Input:** either input alone feeds both sides; polyphonic cables are summed; ±24 V limit into the delay; NaN and inf read 0.
- **Output:** equal-power Mix (0 dry, 1 wet; default 0.35; CV volts / 10 added); soft limit 8 V knee, 10 V ceiling on both outputs; with R unpatched, L carries (L + R) / √2.
- **Bypass:** IN L to L, IN R to R, same normalling. **Saved:** params, `style`, the two latches. **Initialize** and a rate change clear the delay and unfreeze.
- **Rows** on the panel at 64, 83, 102 and 116 mm; columns 7.8, 21.7, 35.56, 49.4, 63.3 mm.

## Review Focus

1. **Clock edges that are irregular, at audio rate, or seconds apart:** T stays inside 10 ms .. Tmax, no divide by zero, no click storm, a stopped clock holds. (Task 3, Task 6.)
2. **Extreme and changing sample rates (1 Hz to 768 kHz), also while frozen or at Feedback 110 %:** no read outside the buffer; Tmax shrinks where the buffer is shorter than 10 s; the delay clears. (Task 2, Task 7.)
3. **Freeze at the shortest time, and GATE toggled at audio rate:** the join never reads outside the loop's own audio, no click, bounded cost. (Task 2, Task 7.)
4. **Time CV at audio rate or in huge steps, in Tape:** the read point stays in the buffer, pitch stays inside two octaves, no NaN. (Task 2, Task 7.)
5. **Feedback at 110 % for minutes with DC, silence or loud noise in:** bounded, no DC building, no denormal slowdown, and the loop dies away once Feedback comes down. (Task 4, Task 7.)

### Task 2: The moving read point (shared)

**Files:** Create `src/DelayTap.hpp`, `src/wake/test_tap.cpp`. Modify `tests.mk` (`PLUGIN_MATH_TESTS`).

**Interfaces — Produces:**

```cpp
namespace rka {
// A read point over a DelayLine the caller writes. Delays in samples.
struct DelayTap {
	void setSampleRate(float fs);
	// Glide: the delay moves toward its target with time constant `seconds`,
	// its slope held so pitch stays within `octaves` either way.
	void setGlide(float seconds, float octaves);
	void setCrossfade(float seconds);
	void snap(float delaySamples);                      // no glide, no fade
	void setTarget(float delaySamples, bool crossfade); // per control tick
	// One sample. `mod` is added to the delay (Drift), in samples. The
	// caller has already written this sample (or not, when frozen).
	float process(const DelayLine& line, float mod);
	// Loop the last `delay()` samples; the line must not be written while
	// frozen. `joinSeconds` is cut to a quarter of the loop if longer.
	void freeze(float joinSeconds);
	void release();                                     // back to the target
	bool frozen() const;
	float delay() const;                                // current, samples
	bool moving() const;                                // gliding or fading
};
}
```

Approach: glide by a per-sample step toward the target, in double, snapping when there is no progress (as Rigging's String); crossfade as two reads with an equal-power fade, a new target taken only when the last fade is done (the latest wins). Frozen: a phase runs 0..loop, reading at delay `loop − phase`; over the last `join` samples it fades to the read one loop older, which is the audio just before the loop's start; `mod` then moves the phase's rate, not the delay. All reads clamped inside `line.maxDelay()`.

- [ ] **Step 1: Failing tests:** `steady`: a ramp written in, the tap at 1000.25 samples returns the ramp delayed by that, within 1e-3. `glide_bends_and_lands`: a 440 Hz sine, target 4800 → 9600: the output's frequency dips, never below 110 Hz, and `delay()` ends at exactly 9600 with `moving()` false. `crossfade_no_bend`: the same step with `crossfade`: zero-crossing rate stays 440 Hz ± 1 % throughout, no sample-to-sample jump over the sine's own slope × 1.5. `latest_target_wins`: three targets inside one fade end at the last. `freeze_repeats`: after `freeze`, with no writes, the output over loop k equals loop k + 1 to 1e-6 for 50 loops, and loop length is `delay()` at the freeze. `freeze_join` (Review Focus 3): noise in the line, loops of 480 (10 ms at 48 kHz), 96 and 16 samples: no jump at the join over 2 × the signal's largest ordinary step; no read beyond `maxDelay()`. `freeze_mod`: `mod` at ±1 % changes the loop's period by that. `bounds` (Review Focus 2, 4): targets of 0, NaN, 1e9 and a target jumping every sample: reads stay finite and inside the line; pitch within the set octaves.
- [ ] **Step 2:** Run. Expected: does not compile.
- [ ] **Step 3:** Implement `rka::DelayTap` in `src/DelayTap.hpp`.
- [ ] **Step 4:** Run; mutate (glide slope unclamped; fade skipped; join length 0); each caught.

### Task 5: The engine

**Files:** Create `src/wake/WakeEngine.hpp`, `src/wake/test_engine.cpp`. Modify `tests.mk`.

**Interfaces — Consumes:** Tasks 2 to 4, `rka::DelayLine`, `hadal::Wander`. **Produces:**

```cpp
namespace rka {
struct WakeFrame {
	enum { TIME, TIME_ATT, FEEDBACK, TONE, RATIO, MIX, DIFFUSE, DRIFT, PARAMS_LEN };
	float params[PARAMS_LEN] = {0.4924f, 0.f, 0.3636f, 0.5f, 3.f, 0.35f, 0.f, 0.15f};
	float timeCv = 0, feedbackCv = 0, mixCv = 0, clock = 0, freezeGate = 0;
	float inL = 0, inR = 0;
	bool inLPatched = false, inRPatched = false, clockPatched = false, outRPatched = false;
	int style = 0;
	bool freeze = false, pingPong = false;        // the latches
};
struct WakeResult { float l = 0, r = 0; bool frozen = false; };
class WakeEngine {
public:
	explicit WakeEngine(uint32_t seed);
	void setSampleRate(float fs);                 // allocates; clears
	void reset();                                 // clears the delay, unfreezes
	void process(const WakeFrame& f, WakeResult& out);
	float maxSeconds() const;                     // Tmax at this rate
	float seconds(int side) const;                // the side's current target time
	int clockStep() const;                        // for the tooltip; -1 unlocked
};
}
```

Per sample, each side: read the tap; smear, then colour; that is the side's loop output and its wet signal. Write: input (to both sides, or the average to the left in Ping Pong) plus Feedback × the loop output that feeds this side. Controls every 16 samples. Buffer: `DelayLine::allocate` for min(10 s, 2^21 samples) plus the join, on `setSampleRate`; `maxSeconds()` follows.
